2026-05-19 [P1] [task-fix-pr22-ui] #user-testing #regression User Testing rounds accumulate geometrically: round1=5 edits, round2=another 5, round4 breaks round3. Without a visual gate the Coder does not see regressions before the PR.
2026-05-21 [P0] [task-profile-redesign] #review-gate #mechanism A Reviewer review event = COMMENT with `Verdict: BLOCK` on the first line of the body (NOT REQUEST_CHANGES) — the GitHub API forbids REQUEST_CHANGES when author == reviewer (one owner for the AI agents). PM parses Verdict: BLOCK → removes awaiting-pm-review → sets do-not-merge → fix-task for the Coder. See Mode 2.D in pm.md.

2026-05-22 [P1] [retro-session-after-archive-pr] #approval #communication Sequence intent ≠ approval. "First we merge X, then Y" is a plan, not a command to merge X now. On any ambiguity ask one clarifying Q: "merge X right now?" — do not assume. Concretely: the premature merge of PR #35 happened because I (PM) read the plan as approval.
2026-05-22 [P1] [retro-session-after-archive-pr] #visual #communication Short visual feedback (a screenshot + 3 words "align vertically") — do not make the first plausible interpretation. Ask one clarifying Q: "align the cells between columns or the contents inside a row?". Concretely: on round 9 I made a 2-row structure for "no junior", but the problem was `min-h-19` on the outer wrapper — a double iteration on one problem.
2026-05-22 [P2] [retro-session-after-archive-pr] #visual #communication For non-trivial visual bugs (a screenshot without annotations) — send the user your interpretation BEFORE dispatching Coder: "I understood that X is needed — correct?". Better to lose 1 round of dialogue than to waste a 12-min Coder run.
2026-05-23 [P0] [dev-flow-rca] #worktree #hygiene ScheduleWakeup does not survive a session boundary. For a cross-session wait (> 30 min) — save `next_action` in `pm-state.json`, and on Mode 3 catch-up on a missed wake-up. See CLAUDE-pm.md section "ScheduleWakeup limitations" + sub-task `task-harness-schedule-wakeup-persistence.md`.
2026-05-23 [P0] [task-pm-cross-session-waits] #wakeup #scheduler The full workaround for D1 — `mcp__scheduled-tasks__*` (an external scheduler survives a session boundary). PM runs `scripts/pm/pm-schedule.sh` to prepare the parameters (fireAt, taskId, materialized prompt), then calls the MCP tool. Each wake-up creates a fresh PM session with a self-contained prompt from `scripts/pm/wakeup-prompts/<template>.md` — no context leak from the source session. Layer 1 (`ScheduleWakeup`) — for in-session short waits; Layer 2 (`mcp__scheduled-tasks`) — for long/critical ones. Do not mix both layers on one wait — it creates duplicate fires.
2026-05-23 [P0] [dev-flow-rca] #silent-completion #recovery A Coder may silently finish without a push (watchdog cutoff). If the Coder does not respond > 10 min after dispatch — read `.claude/tasks/<task>.progress.md` (sentinel), compare `last_update` vs `last_push`. If the gap is > 5 min — `git -C <coder-worktree>` to retrieve the uncommitted work.
