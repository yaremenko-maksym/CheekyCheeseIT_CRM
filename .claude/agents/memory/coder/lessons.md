2026-08-12 [P1] (#mutation-gate #stryker) `// Stryker disable next-line` binds to the STATEMENT, not to the operator: inside a chain (`a.replace().trim().split()`), a multi-line ternary or a JSX expression all mutants are attributed to the FIRST line of the construct, the comment lands on the wrong line and silently has no effect — the gate stays red while the suppression looks done. Fixed by splitting into named statements (also more readable), not by guessing the line number. In JSX children `//` is not a comment at all — it renders as text on the screen, you need `{/* */}` or (better) remove the redundant condition. Insert each suppression in ONE pass bottom-up: each insertion shifts the lines below, and one at a time you get whack-a-mole. Tests that ITERATE the table under test do not catch the mutation (zero out an entry — the loop simply stops checking it): pin with literal pairs. The gate catches real defects too, not only test gaps: on PR #515 it found 23 synonyms that duplicated their own canonical id, and 3 unreachable letters (NFKD decomposes them before the table lookup). The run — MUST be `TZ=UTC` (otherwise locally it counts fewer survivors than CI: on PR #515 CI gave survived 1 vs local 0 — `withTimezone` on a timestamp column was "killed" only because the machine is in UTC+03 while the runner is in UTC) and with `MUTATION_CONCURRENCY=2` (4 workers swap the machine and go slower than two); the local cycle: `MUTATION_BASE_SHA=$(git rev-parse origin/main) MUTATION_PACKAGES=@crm/web MUTATION_CONCURRENCY=2 TZ=UTC node scripts/devops/mutation-gate.mjs --changed`.
