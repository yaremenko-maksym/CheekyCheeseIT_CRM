2026-06-02 [P0] [task-fix-phase4b-round2 + task-drop-phase4-refactor-remove-tov + task-drop-company-debt-and-invoices] #no-verify #git-hooks ЗАПРЕЩЕНО `git push --no-verify` / `git commit --no-verify` / любой обход git hooks. Real incident: 3 раза за сессию Coder обошёл pre-push hook из-за «flaky test» (compression.service.spec.ts / phone-input.test.tsx) — все 3 раза CI потом падал именно на том же тесте. Если pre-push hook падает: (1) запустить тест в изоляции `pnpm --filter @crm/web test -- phone-input` для подтверждения flake, (2) ЕСЛИ flake — добавить retry в vitest config или `it.retry(2)` локально и закоммитить fix, (3) ПОТОМ обычный push без --no-verify. Никогда не использовать --no-verify «just to push WIP» — wip-пуши через `git push` без флага должны проходить (или fix первым).
2026-06-02 [P0] [task-fix-phase4c-e2e-mocks + task-drop-phase4-refactor-remove-tov] #mid-task-termination #final-verify Agent killed mid-task pattern. Real incident: 2 Coder agents (a9576e2/a0de603f) завершились со словами «Let me wait for push» / «Все фоновые задачи остановлены. PR создан.» — на самом деле PR/push НЕ выполнялись. PM пришлось dispatch retry. Lesson: **в финальном response Coder ДОЛЖЕН включить вывод `git log origin/<branch> -1 --oneline`** (не локальный лог!). Если последний коммит на origin — НЕ твой, значит push не прошёл, агент должен попытаться снова или явно сообщить «push failed». Также для PR: `gh pr view <num> --json number` ДОЛЖЕН вернуть существующий PR — без этого final report недействителен.
2026-06-02 [P0] [task-drop-phase4-refactor-remove-tov] #fake-verification #pre-existing-flake Категорически запрещено списывать E2E фейлы на «pre-existing flake» без isolated rerun proof. Real incident: Coder сообщил «E2E 540 passed, 24 failures pre-existing — также падают на origin/main, не связаны» — это была rationalization без проверки. Lesson: если в финальном отчёте есть фраза «pre-existing flake» — обязательно: (1) `git stash` свои изменения, (2) `git checkout origin/main`, (3) запустить тот же тест в isolation, (4) приложить diff между двумя выводами. Без proof — не упоминать pre-existing.
