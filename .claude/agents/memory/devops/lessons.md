2026-08-01 [P0] [prod-outage] #green-signal A green indicator ≠ a working thing — 4 times in one session: post-merge CI green on an unverified main; `/api/health` 200 with the database STOPPED; a green landing build shipping prod without SEO; our own monitor reported success off a broken `grep -c` (multi-line output). Check the SUBJECT, not the signal: not "health 200" but data from the DB (`/api/public/vacancies`); not "there is an ld+json tag" but its type and the number of positions; not "the test is green" but a mutation check (break the code — does it go red?).
2026-08-01 [P0] [prod-outage] #build-vs-prod-data A build that asserts LIVE prod data breaks on content actions. The landing prerender hits the prod API from a headless browser; publishing 3 vacancies on 07-27 at 12:03 added 15 routes, overran the throttler limit (100 req/60s, the whole run in one window) — and the deploy failed for 4 days. Not a line of code changed. Check: how many requests the build makes and into what window they fall.
2026-08-01 [P0] [prod-outage] #deploy-teardown `docker compose up -d <some services>` RECREATES them when compose/env changes (and `.env.production` is rewritten by every deploy) and drags the network along — failing if a service it does not manage is attached to that network (`api` starts later). The step exited with an error, having ALREADY stopped postgres+redis → prod went down. A deploy that takes down the DB must have a recovery path; `down` — only WITHOUT `-v` (the volumes are named, the data survives).
2026-07-27 [P0] [task-infra-post-merge-ci] #workflow-run #blast-radius Fixing a dead trigger WAKES all subscribers of the event. Enabling post-merge CI on main woke the `e2e-watchdog` (`workflow_run: [CI]`) that had slept for 1.5 months, and it pushes to main under ADMIN_PAT → push event → deploy of the red prod → red CI again → loop. Before reviving a trigger — `grep -l "workflow_run" .github/workflows/` and read what each subscriber does with its permissions.
2026-07-27 [P0] [task-infra-post-merge-ci] #gha-steps A GHA step without `if:` = an implicit `success()` of ALL previous steps of the job. Two independent dispatches in a row silently become a chain: if the first failed, the second did not run at all. Gate independent steps explicitly (`if: always() && steps.<id>.outcome == 'success'`). Same inside one `run:` block: the default shell `bash -eo pipefail` aborts the block on the first failure.
2026-07-27 [P1] [task-infra-post-merge-ci] #secrets A non-empty secret check ≠ a validity check. An expired fine-grained PAT is a NON-EMPTY string: `[ -n "$PAT" ]` accepts it, `gh` returns 401, `set -euo pipefail` kills the script before the alert is sent = silence instead of the documented fallback. Pick the channel with a probe request, not with the presence of a variable.
2026-05-20 [P0] [task-infra-merge-gate] #ci-gate CI auto-merge `if: != 'failure'` lets `skipped` through as valid. Use `== 'success'` for each dependent job.
2026-05-19 [P1] [task-infra-e2e-watchdog] #workflow-config A GHA workflow with `permissions: issues: write` must be stated explicitly in the YAML — the default token is read only.
2026-05-23 [P1] [dev-flow-rca] #macos #cross-platform GNU `timeout`/`mktemp` do not work on macOS out of the box. Use shim functions (`_timeout` with a perl fallback) or explicit generation of `/tmp/<prefix>-$$-$RANDOM.<ext>`.
2026-05-23 [P0] [dev-flow-rca] #pkill #worktree-hygiene `pkill -f vite` kills the user's unrelated Vite projects — hostile. Kill processes by PORT (`lsof -ti :PORT | xargs -r kill -TERM`), not by the name pattern. Idempotent.
2026-05-23 [P0] [dev-flow-rca] #worktree-checkout `git checkout BRANCH` fails if the branch is checked out in another worktree. Pre-flight via `git worktree list --porcelain` + `cd` into the found worktree instead of a checkout.
