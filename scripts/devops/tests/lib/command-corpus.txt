# command-corpus.txt — one corpus, run through the three pre:bash hooks by
# test-hook-command-corpus.sh. Added 2026-08-18 after the security review of
# PR #561 found 13 reproduced "main blocked -> PR allows" pairs that hand-picked
# examples had missed twice in a row.
#
# HOW IT WAS BUILT (and how to extend it): materialise the hooks from two git
# refs and run ONE corpus through both, comparing exit codes pairwise —
# scripts/devops/tests/compare-hooks-to-ref.sh does exactly that. Any pair where
# the older tree blocked and the newer one does not is a regression, however
# exotic the form. Selected examples cannot find this class of defect; a corpus
# run in both directions can, and did.
#
# FORMAT (tab-separated):
#   <expect>	<hooks>	<command>
#
#   expect = block     the hook MUST refuse (and carry the decision contract,
#                      so a crash cannot pass for a verdict)
#          = allow     the hook must permit it, AND the old coarse substring
#                      rule (the degraded fallback) permitted it too
#          = narrowed  the hook must permit it although the coarse rule REFUSED
#                      it — a deliberate narrowing. Every such line is a claim
#                      that this refusal was wrong, written down where a reviewer
#                      can see it. If a change ever makes the coarse rule allow
#                      one of these too, the test fails and the annotation gets
#                      corrected rather than quietly rotting.
#   hooks  = comma list of safety | db | ttl  (db = live-db-guard,
#            ttl = devserver-ttl-gate), or `all`
#
# The `narrowed` column is the metric the review named: with a BROKEN analyzer
# `sudo -s rm -rf /etc` was blocked and with a working one it was not — the
# broken guard was stricter than the working one. Every line below is checked
# against both, so that can never again be true of anything except a form
# explicitly listed as `narrowed`.
