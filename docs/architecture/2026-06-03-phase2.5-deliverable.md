## Summary

Swaps `.claude/settings.json` from the legacy `.claude/hooks/*.sh` to the
ECC-format `.claude/hooks-ecc/*.sh` set with stable IDs and ECC matcher
conventions. Adds the new ECC default observer `pre:edit-write:suggest-compact`
per User explicit request. Removes the `eslint-feedback.sh` PostToolUse
entry — superseded by the eslint MCP server (see
`rules/common/eslint-mcp-first.md`).

## Rollback procedure

1. `git revert <merge-commit-SHA-of-this-PR>` on `main`.
2. This restores `.claude/settings.json` to the legacy registration AND
   removes the DEPRECATED comments from the 5 legacy `.sh` files (those
   are kept on disk regardless — only the headers revert).
3. Old `.sh` files were never deleted in Phase 2.5, so the revert leaves
   a fully functional legacy configuration.

Manual fast-path (if revert is impractical mid-session):

- Edit `.claude/settings.json` manually: swap each `hooks-ecc/<name>` back
  to its legacy counterpart per the matrix above; remove the
  `suggest-compact` entry; add back the `eslint-feedback` PostToolUse entry.

## Monitoring (first week post-merge)

Watch the following for unexpected breakage:

1. `<repo>/.claude/pm-state.json` `events` array — look for hook-related
   error strings.
2. `<repo>/.claude/coder-activity.log` should continue receiving entries
   from Coder subagent worktrees on every Edit/Write. If empty after a
   Coder task runs, the post-hook is silently no-oping → investigate.
3. Force-push attempts to `main` should still be blocked by D1c logic.
4. Coder `feature/*` branches must still require `ac_verified:` before
   push — verify by attempting a push from a Coder worktree with a
   non-verified commit and confirming the block reason text matches.

If any of the above misbehave → execute rollback per section above and
file an issue with the failing scenario.
