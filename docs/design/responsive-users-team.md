## 4. UX-H-1 — `UserRow.tsx`: card-stack на `<sm`

### Механизм бага (важно для реализации)

`style={{ gridTemplateColumns: '3fr 1.4fr 64px' }}` — это **inline style**, он побеждает
ЛЮБОЙ Tailwind-класс той же CSS-property, включая `sm:grid-cols-*`. Простое добавление
`className="grid-cols-1 sm:grid-cols-[3fr_1.4fr_64px]"` рядом с существующим `style=` НЕ
сработает — inline style продолжит рендерить 3 колонки даже при `grid-cols-1` в классе.
**Inline `style` нужно убрать целиком** и перенести grid-template в className через Tailwind
arbitrary-value синтаксис: `sm:[grid-template-columns:3fr_1.4fr_64px]`.

### Поведение по классам (мобайл-first)

**`<640` (мобайл, 320/375) — card-stack:**

Строка становится вертикальной карточкой из 3 блоков (сверху вниз), каждый — своя строка:

1. **Identity** (без изменений по составу) — аватар 40px + имя (`truncate`, теперь владеет
   полной шириной карточки минус аватар — не делит место с бейджем роли, поэтому не
   схлопывается) + email/telegram/phone (как сейчас, `truncate` в одну строку) + tech-чипы
   (`flex-wrap`, как сейчас).
2. **Meta-bar** (был правым grid-столбцом с `items-end`, становится собственной строкой
   `flex items-center justify-between`) — бейдж роли (+ бейдж «В архіві», если есть) слева,
   дата — справа. Больше НЕ делит горизонтальное место с identity-блоком → не может наехать
   на tech-чипы (это и была причина оверлапа в UX-H-1).
3. **Actions row** — Pencil/Trash (или Restore для архивных), теперь СТАТИЧНЫЕ (не
   `absolute`, не hover-gated — на тач-устройстве `hover` не работает, см.
   `responsive-design.md` «без hover-only»), всегда видимые, выровнены по правому краю,
   **44×44px** (было `h-7 w-7`=28px десктопного — под тач `≥44px` обязателен, WCAG 2.2 SC 2.5.8
   рекомендует минимум 24px, но проектный стандарт для мобайла — 44px, см. `foundation.md` §10).

**Важно: НЕ дублировать кнопки с `data-testid`.** Один и тот же набор
`user-row-edit-${id}`/`user-row-archive-${id}`/`user-row-unarchive-${id}` должен остаться
**единственным** в DOM на любой ширине — если сделать два разных JSX-блока (один `sm:hidden`,
другой `hidden sm:flex`) с одинаковыми testid, Playwright-локаторы в E2E (которые обычно
гоняются на desktop-вьюпорте) поймают оба элемента и упадут на strict-mode violation. Вместо
дублирования — ОДИН контейнер actions, чьи классы адаптивны:

- Позиционирование: `static` на `<sm` → `sm:absolute sm:right-0 sm:top-0 sm:bottom-0`
- Направление: `flex-row` на `<sm` → `sm:flex-col`
- Видимость: `opacity-100` на `<sm` (всегда видно) → `sm:opacity-40
sm:group-hover/row:opacity-100` (существующее hover-раскрытие сохраняется на `≥sm`)
- Размер кнопки: `h-11 w-11` на `<sm` → `sm:h-7 sm:w-7` (существующий размер не трогаем на
  десктопе)

Пустая 3-я grid-колонка (`<div aria-hidden className="self-stretch" />`, зарезервированная
под absolute-оверлей) на `<sm` не мешает: при `grid-cols-1` она станет пустой auto-height
строкой (0px, без контента) — трогать не обязательно.

**`768` (планшет) и выше — без изменений.** Уже подтверждено live-прогоном (см. ниже):
на 768 текущая 3-колоночная раскладка усекает длинные значения многоточием, но не ломается —
имя видно частично, бейдж роли не накладывается. `sm:`-брейкпоинт (640px) — безопасная
граница: мобильный fix применяется строго ниже него, 768 продолжает получать нынешний grid
без изменений.

**`1024`/`1280`/`1440`/`1920` — без изменений**, подтверждено live-прогоном (скриншот
1440, EN-локаль — см. ниже): полная 3-колоночная раскладка, имя/email/чипы не обрезаны,
бейдж роли и дата аккуратно в правом столбце.

### A11y

- Touch target actions-кнопок на мобайле — 44×44px (сверх WCAG-минимума 24px).
- `aria-label` на Pencil/Trash уже включает имя пользователя (`t\`Редагувати ${user.displayName}\``)
  — не менять, уже корректно.
- Порядок фокуса (Tab) не меняется структурно — DOM-порядок остаётся Identity → (meta-bar не
  фокусируемый) → actions; визуальный `order-*` в CSS не переставляет DOM-порядок, так что
  screen-reader/Tab-порядок остаётся предсказуемым (сверху вниз, как выглядит на мобайле).

## 5. UX-H-2 — `team/index.tsx`: card-stack на `<sm`

### Поведение по классам

**`<640` (мобайл) — card-stack, порядок «имя+HR сверху, аватари+пилюли снизу»** (буквально
формулировка из finding'а UX-H-2, «Suggested fix»):

Контейнер карточки: `flex h-14 items-center gap-3` (фикс-высота, без переноса) →
`flex flex-col gap-2 py-3` на `<sm`, `sm:h-14 sm:flex-row sm:items-center sm:gap-3 sm:py-0`
без изменений на `≥sm`.

Три текущих ребёнка (Avatars / Name+HR / Pills) переставляются ТОЛЬКО визуально через
`order-*` (не через перестановку в DOM — DOM-порядок и порядок чтения screen-reader'ом
остаётся как в текущей разметке; `order` — исключительно visual reflow):

- Name+HR блок → `order-1 sm:order-none` (на мобайле идёт первым)
- Avatars блок → `order-2 sm:order-none`
- Pills блок → `order-3 sm:order-none`, плюс `flex-wrap sm:flex-nowrap` — это и есть фикс
  «крайний бейдж обрезан правым краем»: пилюли (Telegram / «N учасників» / «N проєктів» /
  бейдж архива), которые сейчас все `shrink-0` в нерастягиваемом ряду, при нехватке места
  переносятся на вторую строку вместо обрезания overflow-hidden контейнера карточки.

При `flex-col` каждый ребёнок по умолчанию (`align-items: stretch`) растягивается на всю
ширину карточки — значит Name+HR блок получает **всю** ширину карточки вместо доли, которая
раньше конкурировала с аватарками и пилюлями (именно это раньше схлопывало его до 0px).
Явно `flex-1`/`min-w-0` на этом блоке можно оставить как есть (безвредно в column-режиме),
НО она относится к main-axis (вертикали) в column-контексте — если это создаёт нежелательный
вертикальный рост, ограничить её через `sm:flex-1` (эффект `flex-1` нужен только в
desktop `flex-row`).

**`768` и выше — без изменений.** Подтверждено live-прогоном (см. ниже, скриншот 768,
EN-локаль): при текущей 3fr… раскладке имя усекается многоточием («Team Kov…», «Команда
Roman Drobot…»), НО не схлопывается до 0 и не перекрывается пилюлями — приемлемо, менять не
нужно. Тот же `sm:` (640px) брейкпоинт безопасен.

**`1024`+ — без изменений**, подтверждено скриншотом 1440.

### Второстепенное замечание (НЕ обязательный AC, для осведомлённости кодера)

Telegram-пилюля (`<a href=... className="... px-2.5 py-1 ...">`) на мобайле после этого фикса
остаётся кликабельной ссылкой размером примерно 28px по высоте — ниже мобильного стандарта
44px. Это pre-existing, не introduced этим фиксом, и не входит в находки UX-H-2/L-1 — можно
взять отдельным follow-up вместе с тем же тулбаром `/team` (см. §1 «Что НЕ трогаем»). Не
блокирует эту задачу.

## 6. UX-L-1 — `ShareSlider`: бар не клипается на узком контейнере

### Механизм бага

`{pct}% {label}` рендерится ВСЕГДА, когда `pct >= 12`, независимо от АБСОЛЮТНОЙ ширины
контейнера в px — при узком контейнере (320px-диалог) даже сегмент с `pct=26` (>=12,
проходит текущий гейт) физически недостаточно широк для текста «26% сеньйора». Из-за
`items-center justify-center` в контейнере с `overflow-hidden` обрезание идёт симметрично с
обоих краёв текста — отсюда характерный артефакт «26% сеньйора» → «6% сеньйор» (потеряны
крайние символы с обеих сторон, а не только справа).

### Фикс

Единственный известный контекст использования `ShareSlider` — диалоги, чья ширина на мобайле
равна ширине экрана минус паддинг (полноэкранный `CrmDialog` на `<sm`, `sm:max-w-md` на
`≥sm`). Значит вьюпорт-брейкпоинт `sm` — надёжный прокси для «сегмент физически слишком
узкий», и особый JS-замер ширины не нужен.

Внутри обоих сегментов (`company` и `role`) — суффикс-лейбл (` сеньйора`/` дропа`/`
компанії`) скрывается на `<sm` НЕЗАВИСИМО от `pct`, показывается на `≥sm` по прежнему условию
`pct >= 12`:

```
{pct}%<span className="hidden sm:inline">{pct >= 12 ? ` ${label}` : ''}</span>
```

На `<sm` бар всегда показывает голое `NN%` (максимум 4 символа «100%») — влезает в любой
сегмент шире ~20px, что тривиально выполняется при любом разумном split (1–100%) на
320px-баре. `title="{pct}% {label}"` на контейнере сегмента (уже есть, не менять) продолжает
раскрывать полную подпись по hover/long-press — доступность подписи не теряется, только
способ её показа на мобайле меняется с «всегда видимый текст» на «по требованию».

`aria-label` на `<input type="range">` и `<input type="number">` уже несёт полную фразу
(`Частка сеньйора у відсотках`) независимо от видимости текста в баре — screen-reader не
затронут.

Т.к. `ShareSlider` — общий компонent (5 точек использования, см. §1), фикс в одном файле
(`share-slider.tsx`) автоматически чинит ту же проблему в `UserDialog.tsx` (SENIOR/DROP share
при создании/правке) и `team/$teamId.tsx` (per-project override), даже если она не была явно
заскриншочена в находках — тот же корневой механизм, тот же компонент.

## 7. Edge cases

- **Длинное имя пользователя** (UK: составные фамилии, EN: длиннее среднего) — `truncate` на
  identity-блоке уже есть, card-stack не меняет этот механизм, просто даёт ему больше ширины
  (было `3fr` от 320px минус остальные колонки ≈ узко; теперь вся ширина карточки).
- **Длинное название команды** — то же, `truncate` на `.team-name`, не меняется.
- **0 tech-чипов / 0 участников команды** — блоки не рендерятся (уже так, `techStack.length >
0` / `team.members.slice(0,4)`), card-stack не добавляет пустых промежутков сверх обычного
  `gap`.
- **Архивная строка** (`UnarchiveButton` → тот же `UserRow`) — actions-row вместо
  Pencil+Trash показывает один Restore, тот же адаптивный контейнер применяется без доп.
  логики (проверено по коду: `isArchived` только переключает JSX-содержимое actions-блока, не
  его layout-классы).
- **DROP-бейдж на карточке команды** — на mobile теперь в Pills-блоке (order-3) рядом с
  «N учасників»/«N проєктів», с `flex-wrap` — при длинном combo (Drop + Telegram + оба
  numeric-бейджа) корректно переносится на вторую строку вместо обрезания.
- **0%/100% на ShareSlider** — уже отработанный текущей логикой edge case (`min`/`max` пропсы,
  `clamp`), фикс §6 его не трогает — голый `%` умещается в любом случае.
- **`sortKey`/toolbar на `/users`** — уже `flex-wrap` (см. `CardContent className="flex
flex-wrap items-center gap-3"` в `routes/_authenticated/users/index.tsx`), не требует правок.

## 9. Как проверялось и почему нет PNG (design-gate: degraded)

Живой прогон этой сессии (dev-стек: scratch-БД `crm_qa_uxresp`, API `:3021`, web `:3020`,
dev-login ADMIN/HR, Playwright MCP) воспроизвёл **все три** находки буквально, вплоть до
символов:

- `/users`, 320px, uk: имя строки #1 — «Ан...» (полное «Анна Лисенко»), строки #2 — голое «A»
  (имя пропало полностью), бейдж «Сеньйор» наложен на чип «React».
- `/users`, 375px, en: «Anna Lys…», «Artem Kr…», email «art… @ +.» — частично читаемо, хуже
  чем uk (английские имена/email длиннее).
- `/team`, 320px, uk: название команды невидимо на ВСЕХ карточках (нулевая ширина), «Дроп»
  наезжает на «3 учасники», последний бейдж на карточках с Telegram обрезан по правому краю
  («5 уча…»).
- Диалог «Створити сеньйора» (HR-роль), 320px, uk, `ShareSlider` при значении 26 (дефолт):
  текст в правом сегменте — «6% сеньйор» (буквально как в находке `UX-L-1`).
- 768/1024/1440, uk/en — раскладка не ломается (имя усекается многоточием на 768, полностью
  видно на 1024+), подтверждает, что `sm:`-брейкпоинт достаточен и выше него менять нечего.

Причина отсутствия PNG-файлов в этом репозитории: Playwright MCP-инструмент в этой сессии
программно ограничен (`allowed roots`) каталогом ДРУГОГО (оркестраторского) worktree —
попытка сохранить скриншот по абсолютному пути в worktree этой задачи вернула `File access
denied: ... is outside allowed roots`. Писать в чужой worktree запрещено
`.claude/rules/common/agent-isolation.md` (§4 «Чужое дерево не мутируется. Никогда»), поэтому
скриншоты, сделанные относительным путём, физически остались в чужом каталоге
(`docs/design/assets/responsive-users-team/before-*.png` в worktree
`paid-transaction-edit-cascade-d0b6d1`) — их нельзя ни перенести оттуда (Bash-хук
`cross-agent-blast` блокирует любую команду, упоминающую тот путь), ни удалить оттуда тем же
образом. **Это сообщается оркестратору отдельно** — файлы там не содержат ничего чувствительного
(скриншоты этого же публичного UI), но лежат не там, где должны, и не закоммичены (worktree
чужой сессии).

Вместо PNG — `docs/design/assets/responsive-users-team/design-320.html`: самодостаточный
HTML-макет предложенного состояния (card-stack `/users` + `/team` + `ShareSlider`-фикс),
собранный на реальных значениях `oklch()`-токенов из `globals.css` (тёмная тема, единственная
в проекте). **Это референс намерения, не код для вставки** — кодер строит фикс НАШИМИ
компонентами (`Badge`, `Button`, существующая структура `UserRow`/`team/index.tsx`) по
описанию классов в §4–6 этого файла, а не копирует HTML.

Для ≥640 (768/1024/1280/1440/1920) отдельного макета не нужно — эта задача НЕ меняет
раскладку на этих ширинах, так что текущая реализация на `main` УЖЕ является корректным
fidelity-референсом (подтверждено live-скриншотами в этой сессии, см. выше).
