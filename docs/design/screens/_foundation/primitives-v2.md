## 2. Sheets and panels

**Medium sheet** (`sheet-medium-*`): filters and short forms (≤ 4 fields). Top at ≈ 46% of the
viewport (36% at 320 so the content fits), `--radius-sheet` corners, drag handle (36 × 5, hit area
44), title row with «Скинути» on the left (resets the filters to their defaults) and a 44 px ✕ on the
right (closes and **discards unapplied filter changes**); the apply action «Показати 48» sits in the
bottom bar. Drag up expands to large; drag down past 30% or a fling dismisses. Scrim
`--scrim`.

**Large sheet / `ResponsiveSheet`** (`sheet-large-375`): long forms and edit. Full height minus the
status bar. Chrome, the same on every mobile form: «Скасувати» top-left, title centred, **nothing
top-right**; the primary («Зберегти») sits in a bottom bar above the home indicator, or on the
keyboard when it is open. The pushed form page (`form-money-375`) uses the same bottom bar. The primary
is **always enabled** except while its own request is in flight (§4 Submit). **A dirty form asks
before it closes** (drag, scrim, Скасувати) with an action sheet. A **money draft** is the exception:
while it is armed, failed or unknown the leading control reads **«Згорнути»**, and drag, scrim and
«Згорнути» all close the sheet and **keep** the draft, with no confirm. Discarding a failed or unknown
draft is its own 44 px control «Видалити чернетку» under the primary, which opens the named confirm
(§4; foundation §11).

**PickerSheet** (`picker-sheet-375`, project picker over the money form, keyboard closed): one medium
sheet for every single choice from a long list: **project, user, currency, role**. Title names the field
(«Проєкт»), 44 px ✕ on the right (closes, nothing changes). A **sticky 44 px search** (16 px text) sits
under the title; rows are 56 px `role="option"` inside a `role="listbox"`; the current value carries a
yellow checkmark and `aria-selected="true"`. Order: for project, the «Без проєкту» row first; then
«Нещодавні» (last used on this device, newest first); then the full list alphabetically. A tap selects
and closes the sheet; focus returns to the field. Currency and role are short: same sheet, no search
under 8 options.

**Action sheet** (`sheet-confirm-375`): destructive confirm on touch. Message names the object
(«Видалити транзакцію «Оренда офісу»?»), destructive action in `text-destructive`, «Скасувати» as a
separate bold group. `role="alertdialog"`, focus starts on «Скасувати».

**Side panel** (`sheet-panel-*`): preview and edit on tablet / desktop. **Width (R4-25, the one
rule for every width):** 400 at 640–1023 (tablet, touch heights 48 / 44, modal over the scrim); 420 at
1024–1439 under either pointer (modal over the scrim; `datepicker-popover-touch-1180`); 480 at ≥ 1440
(non-modal, in the flex row). Header with title + close; sticky footer with the primary
action. **An edit prefills every field of the record, its project included (R4-03: «Оренда офісу» opens with «Альфа», never «Без проєкту»).** **One panel body at every width (F0-07, R3-03):** the canonical money form of §4; `sheet-panel-768`
draws it at 400 px with touch sizes (48 px inputs, 44 px ✕, «Замінити» and footer buttons).
The scrim covers the rail too. On touch the panel also closes by a drag from its left edge to the right
(past 30 % of its width, or a fling); ✕, Esc, a scrim tap and system back close it as well. A **new**
money transaction on the tablet opens the canonical `moneyBody()` in the same 400 px panel (receipt
switch, defaults row, «Скасувати» / «Зберегти»). Where
drafts start, where the pill lives and where «Перевірити список» opens per size: `shell-v2.md` §4
«Money drafts per size». Shortcut hints («Esc», «⌘↵») show **only
under `(pointer: fine)`**: the 1024 / 1440 panels have them, the touch tablet does not. **Modality by width.** At ≥ 1440 the edit / create panel is **non-modal**: no `aria-modal`, no focus trap, no scrim, and the table beside it stays interactive. Clicking another row while the panel is dirty runs «Вийти без збереження?» first (§4); a clean panel swaps its content to the new row. Esc closes the panel only when focus is inside it. Below 1440 the panel is modal: focus trap, scrim, Esc closes. (Council R12 proposed a modal panel at every width; rejected, because the ≥ 1440 layout exists to keep the table usable beside the form.)

**Confirm dialog** (`sheet-confirm-dialog-1024`): 440 px centred alert dialog; initial focus on
«Скасувати»; Enter does not trigger the destructive action.

**Session alert** (`alert-session-expired-375`): the action sheet built the same way, «Увійти знову» and
«Не зараз». The secondary never reads «Скасувати», because the form behind it uses that word to discard.
When the body names a loss (a dirty form, a draft by amount, an unknown draft's sent data; the unknown draft never reads «втрачено», because its marker stays), the initial
focus is on «Не зараз» and Enter does not sign in. When and why it shows, and the banner after «Не зараз»: foundation §11.

## 3. Lists

**List row** (`listrow-variants-375`): 56 px single-line / 64 px minimum with a meta line (it grows when the meta wraps, §12.0), inset separator at 16.
Leading: 40 px avatar or 32 px icon tile. Primary line 16/22; secondary 15/20 muted; trailing value
right-aligned, `tabular-nums`, with sign (`+` positive, `−` destructive) and a status word or badge.
Pressed state `bg-accent`. Variants: navigation (chevron), value, toggle, destructive.

**At 768 / 1440** (`listrow-768`, `listrow-1440`): the tablet keeps the touch row (56 / 64, target ≥ 44).
**640–899 is a single pane with push**: the list takes the full width and a row pushes its detail, so
there is no selected-row highlight (no `aria-current`, no `--raised` selection tone). From **≥ 900** list and detail
sit side by side (`shell-v2/tablet-two-pane-1000`: rail 80, list 400, detail the rest, 520 at 1000)
and only there the selected row carries the one selection cue of §12.0 (`--raised`, a 2 px `--primary` bar, `aria-current`). The desktop row is a 40 px table row (states default / hover / selected / focus ring 2 px /
pending; the selected row carries the one selection cue of §12.0: `--raised`, a 2 px `--primary` bar, `aria-selected`) and a
36 px sidebar row; the full row is the hit area. Under `(pointer: coarse)` the table row is 52 and every sidebar row and group header 44, the collapsed rail controls too (`shell-v2/shell-touch-1180.png`, `shell-v2/shell-touch-collapsed-1180.png`; §12.0).

**Empty and error inside a list** (`listrow-empty-error-375`): a filtered-empty block («Немає транзакцій
за цим фільтром» + «Скинути фільтри»), an empty group (one muted row, no illustration) and a failed group
(`role="alert"` row + «Повторити»). That «Повторити» re-reads data only; a money write is never retried
from a list.

**List footer** (`list-footer-375`): the paging states at the end of a loaded list. The next page
loading shows 3 skeleton rows under the loaded ones (`role="status"` «Завантаження ще транзакцій», the rows
`aria-hidden`). The next page failing shows one inline row in their place, «Не вдалося завантажити ще» with a
44 px «Повторити» (`role="alert"`), and the loaded rows stay. The end of the list shows no footer. Back from a
pushed detail restores the scroll position and every loaded page; it never resets to the first page. Like the
group «Повторити», this one re-reads data only. The error copy wraps to two lines and is never clipped
(`list-footer-320`). **What loads the next page:** it loads by itself when the last rows enter the viewport, except while a search is active (below).
After an error only «Повторити» retries; scrolling does not.

**Search on a paged list** (`search-paged-375`): while more pages exist, a search filters only what is
loaded, so it says what it covered. The results end with «Шукали серед завантажених, з 9.11 · Шукати далі» (the oldest loaded date; «з» reads as "since", where «до» would read as "before"); with no results the same line replaces the plain empty text. **While a search is active, auto-load is off**: reaching the end loads nothing by itself. «Шукати далі» loads pages until the first new match or 5 pages, whichever comes first, then the line updates its date; the button keeps its place, so another tap goes on. **States:** while it runs, the button shows a spinner and is `aria-disabled`; the result is one `role="status"` line, «Знайдено ще N» or «Нових збігів немає · шукали з 2.11»; a failure reuses the list-footer error row (above) (`search-paged-states-375`). **≥ 640 (R3-29):** the same line and button sit at the end of the list pane on a tablet (44 px button, `list-footer-768`) and as the last row of the desktop table (36 px button under a fine pointer); the date always follows «з» with a no-break space. The line goes away once the last page is loaded, and editing the query cancels the run. Where the list API accepts a search parameter, the search goes to the server and the line
never appears (foundation §11 Wave 1 AC).

**Swipe actions** (`listrow-swipe-375`): trailing edge only (no leading swipe: it collides with system
back). Revealed actions «Редагувати» (secondary) and «Видалити» (destructive), each 88 px wide and the row height; the words are the row menu’s. A
full swipe does **not** delete; it asks with the action sheet. **Single-pointer alternative**
(SC 2.5.1 / 2.5.7): the one rule is §12 «Row actions and the «…» trigger». On the phone a row with a pushed detail carries the same actions in its detail page and shows no «…»; a row without one shows a visible 44 px «…». A long-press is a shortcut to the same menu, never the only path. Rows set
`-webkit-touch-callout: none` so the long-press does not raise the iOS link / image callout.

**Pushed detail page** (`detail-txn-375`, `detail-person-375`): the target of a row with a detail, and
the home of that row's swipe actions. **No bar title at rest** (the iOS Contacts pattern): the head's
text («Оренда офісу», the person's name) is the page `h1`; once the head scrolls under the bar it
becomes the centred inline title when it fits (the inset and the 120 px minimum: `shell-v2.md` pushed
screen; `detail-txn-scrolled-320`). Back on the left (a real `<button>`, `aria-label` «Назад»); on the right a 44 px text button
«Редагувати» (the edit entry) and a 44 px «…» (`aria-label` «Інші дії», `aria-haspopup="menu"`) for the
rest (delete asks with the action sheet). **Transaction:** the description, the amount 40/46 700
`tabular-nums` (never truncated), **one status-pill slot** under it («Оплачено» here), then one
key-value group (Тип, Платник, Отримувач, Дата, Проєкт as a link row `<a>`, Створив; long values wrap,
they do not truncate), then «Чек»: a 56 px thumbnail row, a real `<button>` («торкніться, щоб
збільшити», `aria-label` «Переглянути чек на весь екран»). This body is the one detail anatomy: the
≥ 900 detail pane renders the same component (`shell-v2.md` §3). A link receipt is the
same row with the host name and opens in the browser. The tap opens the **full-screen viewer**
(`detail-txn-receipt-375`): a `role="dialog"` on black, the file name, a 44 px ✕ «Закрити» top-left,
pinch and double-tap to zoom, Esc and a swipe down also close, focus returns to the thumbnail.
**Person:** a 72 px avatar with initials, name, «роль · команда», then «Контакти» as tappable 56 px
rows (`tel:`, `mailto:`, Telegram; the accessible name says the action, «Подзвонити: …»), then
«Робота» (Роль, Команда and Проєкти as link rows).

**Sticky section header** (`listrow-sticky-320`, `section-header-375`): overline 12/16 uppercase, 92%
translucent bar with blur while stuck; date sections show the day total on the right (`tabular-nums`; per currency, «−186,40 USD · −3 000,00 USDT», never summed across currencies). A date header whose day continues past the
loaded page hides its total until the next page loads (no extra request).
**Row rule:** §12.0 holds it for every row at every width (`listrow-sticky-320`, `list-footer-375`, `list-footer-320`, `listrow-768`); no other passage restates it.

**Board** (`board-1440`, `board-768`, `board-stage-sheet-375`, `board-undo-375`, `board-hire-confirm-375`; today the interviews pipeline). At ≥ 640: one column per active stage; **column widths are the one rule in §12 Board (R5-14)**. When the stages do not fit, the board scrolls sideways: a fade on the clipped edge, plus a visible scrollbar for the mouse (`board-768`, `board-1440`). A touch drag held within 48 px of the board's left or right edge scrolls the board that way. The column header holds the stage name and its count
(`tabular-nums`; the accessible name reads «Технічна, 2»). A card shows initials, the name (wraps, never
truncates), one muted line (role · project) and a date (`tabular-nums`). **Card states:** rest; at a fine pointer, hover or focus shows a 32 px «Змінити етап» button in the top-right corner (tooltip «Змінити етап (M)»; focus ring per foundation §13); under `(pointer: coarse)` that button is always visible with a 44 px hit area (foundation §13, `board-768`); the **drag
source** stays in place at 35 % opacity with a dashed border; the **lifted card** follows the pointer,
raised (`--raised`, shadow) and never rotated. The **drop target** column gets the yellow-subtle fill, a
dashed `--primary` outline and a dashed slot where the card will land. A polite live region narrates the
drag («Олена Коваль: над «Технічна». Відпустіть, щоб перемістити, або Esc, щоб скасувати.»); Esc cancels and the card goes back. Under a coarse pointer a drag starts only after a ~250 ms press (5 px tolerance); a shorter swipe scrolls the board. A failed move returns the card to its column with an inline error on the card; nothing else moves.

**Undo, except «Найнято»:** every move (drag, picker, `M`), «Відмова» included, shows the undo toast «Олена Коваль → Відмова · Скасувати» for 5 s and asks nothing (§6, `board-undo-375`). **«Найнято» is not reversible:** the move creates a project in the same transaction, and moving the card back keeps it. So a move to «Найнято» (drag, picker or `M`) first opens a named confirm «Перевести Олена Коваль у «Найнято»?» with «Буде створено проєкт.», «Перевести» / «Скасувати» (`board-hire-confirm-375`); a dropped card waits in its old column until the answer. After «Перевести», a plain result toast without «Скасувати».

**Keyboard move:** Tab reaches each card and Enter opens it. `M` (only while a card has focus, so SC 2.1.4
holds) or the card's «Змінити етап» button opens the «Етап» picker, a popover listbox at ≥ 640 with the
current stage checked. Arrows and Enter move the card; focus stays on the moved card in its new column. The picker is the only keyboard path: the build drops dnd-kit's keyboard sensor (Space-lift), so drag is pointer-only. `M` is listed in the `?` sheet («Списки») and in the button's tooltip.

**Single pointer (SC 2.5.7) and the phone:** the «Змінити етап» button opens the same picker, so no move
needs a drag. The phone has no drag: the board is the stage-filtered list, and a row's «Змінити етап»
action (its detail page or the row menu) opens the «Етап» PickerSheet (`board-stage-sheet-375`); the move then shows the same undo toast (`board-undo-375`), or for «Найнято» the confirm first (`board-hire-confirm-375`). The sheet
shows the candidate line under the title, the active stages with the current one checked, then
«Завершити» with «Найнято» and «Відмова».

## 4. Forms

**Field states** (`form-states-375`, a profile edit «Редагувати профіль»): label above (15/20), input
48 h (mobile) / 36 h (desktop), 16 px text, `--input-border` outline, `--placeholder` text. The frame
shows filled, focus, error, a PickerSheet field (Роль, enabled: a tap opens the PickerSheet) and a
disabled field with its reason («Email для входу» · «Прив’язаний до Google-акаунта»). Focus: yellow border + 3 px soft ring. Error:
destructive border + icon + message under the field (`aria-describedby`, `aria-invalid`). Disabled:
50% opacity + dashed border + a reason line («Роль змінює адміністратор»). Helper text 13/18 muted.

## 7. Pull-to-refresh and transitions

**Pull-to-refresh** (`ptr-*`, drawn with the tab bar so the scroller bounds are honest): pulling
(arrow), armed at 64 px (arrow rotates 180°, turns yellow; no haptics — iOS Safari has none), refreshing (spinner, content held at 50 px), done («Оновлено щойно», 1 s, then collapses).
Only on tab-root lists **of the phone layout (< 640, R5-24)**; the rail (640–1023) and sidebar (≥ 1024)
layouts have no pull-to-refresh: their lists refetch on window focus, on route entry and on the poll; the
manual refresh there is the browser's own reload (the queries refetch on mount), so no extra control is drawn. Under reduced motion the arrow does not rotate; the state text changes instead.
Rules from spec §4.2: the gesture lives on the **list scroller only** and **refetches that list's query**
(other queries on the screen are untouched); it **never reloads the page**; it is **off while a sheet is
open**. iOS Safari's own page pull-to-refresh is not reliably disabled by `overscroll-behavior`, so Wave 0
proves on the iOS Simulator that a sheet drag at `scrollTop` 0 and a pull on a list never reload the
page (acceptance criterion).

**Transitions** (`transition-storyboard`; R4-26 adds the desktop side panel row: 1024–1439 modal over the `--scrim` as on the tablet, ≥ 1440 non-modal with no scrim while the main column narrows in the same 280 ms): push / back 280 ms slide + fade (View Transitions), tab switch
instant, sheet 280 ms up / 150 ms down, side panel 280 ms in / 150 ms out, dialog 200 ms (fade + scale 0.96→1) / 150 ms fade out, popover and menu 200 ms (fade + 4 px from the anchor) / 150 ms fade out, desktop route 150 ms crossfade; every scrim fades 0 → `--scrim` (0.6) in 200 ms (R3-11, one value); reduced motion = 120 ms crossfade for every one of them, scrims included.

## 9. A11y critical paths

- Sheets, panels and dialogs: focus trap, Esc closes, focus returns to the trigger; drag has a button
  alternative. The one exception is the ≥ 1440 edit panel: non-modal, no trap (§2 Side panel).
- The board never needs a drag: «Змінити етап» on every card (and `M` on a focused card) opens
  the «Етап» picker; the phone has no drag at all.
- Swipe and long-press actions have a single-pointer path: the row's detail page, or a visible 44 px
  «…» on rows without a detail.
- Hover never hides a control: under a coarse pointer every hover-revealed control (the board's «Змінити
  етап», a row's trailing delete) is always visible at 44 px (foundation §13).
- The money-form primary is never disabled for validity; a tap moves focus to the first invalid field.
  In flight it is `aria-disabled="true"` with its spinner, never `disabled`, so focus stays on it.
- Every interactive element is a native `<button>` or `<a>` (rows with a detail, contact rows, the
  receipt row, the top-bar actions, chips, the switch, PickerSheet fields); no `role="button"` /
  `role="link"` on a `div` or `span`. `prims-mobile.mjs` and `tablet.mjs` follow it; the older money
  form and shell sources (`money-form.mjs`, `mobile.mjs`, `mobile-overlays.mjs`, `base.mjs`) still
  draw `role="button"` spans as drawing shorthand. The mockups are a visual reference, never markup
  to copy.
- Errors: `aria-invalid` + `aria-describedby`; save error `role="alert"`; toasts `role="status"`.
- Progress (receipt ring, upload pill, armed fill) is `role="progressbar"` with `aria-valuenow`; one
  visually hidden `role="status"` per surface announces milestones only (started, finished, failed),
  never each percent (foundation §11).
- Action-sheet rows (`actionConfirm`) are real `<button type="button">` elements, never a
  `div role="button"`.
- Charts: a text summary («Чистий прибуток за 6 місяців: …») as the accessible name; bars focusable.
- Every coarse-pointer target ≥ 44 × 44 (foundation §4), including segments, the currency pill, chips,
  search, the period control, «Скасувати» in toasts, small buttons and chevrons, sidebar rows and group headers, the collapsed rail controls, DateField cells and «Сьогодні», a row’s «…» trigger and its menu items (tooltips are not drawn under touch); inputs ≥ 16 px; contrast
  per foundation §7.

## 12. Council rules (r1, r2)

The single rule text of this file. A rule stated anywhere else is a pointer to this section; where an older passage or a frame disagreed, it was rewritten or re-rendered in r2 (ledger R1-00). Each rule names its finding id; the two ledgers below map every id.

### 12.0 Row anatomy (R1-00, the one rule)

The only text that states how a row wraps, truncates, selects or reserves space.

- **Title (R2-36):** wraps to **two lines at most** in a list row (a clamp with `overflow-wrap: anywhere`), so the part of a name that tells two records apart («Зарплата · Розробник 4» from «… Розробник 2») is never cut; only a third line ends in an ellipsis, and the full text is the accessible name (`listrow-768`, `listrow-sticky-320`). The amount stays on the first line at the trailing edge, so a two-line title costs the row one line (72 px with a one-line meta). **A desktop table cell is the exception, an assumption (A1, reversible): one line, an ellipsis and the full text in a tooltip at a fine pointer**, because the table row is a fixed 40 px (52 coarse) and «Опис» is the widest column (`listrow-table-desktop`).
- **Meta:** wraps, two lines at most (a clamp with `overflow-wrap: anywhere`); the row grows with title and meta, so 56 / 64 px are minimums. Order: status when there is one («Очікує», «нова», «збіг», «схожа», «Не збережено»), then time, the receipt clip, type, project: «Очікує · 14:20 · Витрата · Проєкт «Альфа»»; the status always comes before the type. A tag that names a difference leads the meta whole, like «збіг» («схожа · інший опис · 14:33 · …»), never a line of its own (R4-23). **Table «Опис» (R4-28):** when the project rides in the description cell («Опис · Проєкт», widths without a Проєкт column), the project is atomic: drawn whole after the description or not at all, so the description truncates alone and the cell never ends «· А…»; the project stays in the accessible name (`sheet-panel-1440`). **The disclosure chevron** uses `--chevron` (≥ 3:1 on every list surface, `contrast.mjs`; R4-18).
- **Separators (R5-28, supersedes R3-14):** a meta line joins its parts with «·» that has a normal space before it and a no-break space (U+00A0) after it, so a line may break only before a separator: the «·» binds to the part after it, a part is never split from its own words, and no line ends on a dangling «·» (a wrapped line starts with «· part»). A word that governs the next value binds to it too («з 9.11», «о 14:33»). Every frame uses this form (the generator applies it); `strings.mjs` `dangling` fails any frame with a line that ends on «·» (`board-768`, `board-1440`, `listrow-draft-375`, `tablet-two-pane-1000`).
- **Never truncated:** an amount, a percentage and a time (R1-22). Each is `white-space: nowrap` with `tabular-nums`, and a currency code stays with its number. The amount sits alone on the title line at the trailing edge and does not shrink.
- **Trailing zone (R1-04):** fixed, no per-row inset. A money list (Фінанси) on a phone docks its create action (D-8): a 64 px strip above the tab bar (a 48 px «Нова транзакція» primary button, 8 px padding, solid `--bg`, hairline top border); the other tab-root lists keep the FAB. Bottom padding: the one formula of shell-v2 §2 (R3-12), so no amount is ever covered. On Фінанси the pill and the toast span the width and sit 16 px above the dock; elsewhere they keep their 80 px right inset beside the FAB.
- **Selection (R1-28):** `--raised` fill, a 2 px `--primary` leading bar, and `aria-current` (list pane) or `aria-selected` (table). Pressed is `--accent`. No other selected token.
- **Totals (R1-03, R1-23):** day, section and chart totals are per currency, never summed across currencies. Every frame fixture states its parts, and the generators assert it (`mobile.mjs` `dayTotal`; the chart guard in `prims-viz.mjs`).
- **Coarse pointer (R1-01, R1-09):** every target is 44 px: sidebar rows and group headers, collapsed-rail controls, DateField cells and «Сьогодні», a row’s «…» trigger and its menu items; a table row is 52. `measure.mjs` checks `.srow`, headers, links and every `[role=button]` under touch.

### Row actions and the «…» trigger (R2-30, the one rule)

- **Phone (< 640):** a row with a pushed detail has no «…» (the swipe, the detail page and the long-press shortcut carry its actions); a row without one (a file, a receipt) shows a visible 44 px «…» (`aria-label` «Дії: {title}», `aria-haspopup="menu"`).
- **Tablet and desktop (≥ 640): every list row and every table row has the «…» trigger**, the selected row and the rows of a two-pane list included. It sits in one trailing slot of fixed width: 44 px in a tablet list row, a 48 px table column holding a 36 px button (44 under a coarse pointer). The slot is reserved even while its button is hidden, so nothing shifts when it shows. At a fine pointer the button shows on hover, on focus and on the selected row; at a coarse pointer it is always visible.
- Every frame of a list or table draws the slot: loaded, skeleton (a grey circle in the slot at a coarse pointer; the empty reserved slot at a fine pointer, R3-08), empty, error, footer, banner and the rows under an open menu or panel (`tablet-two-pane-1000`, `skeleton-768`, `list-footer-768`, `row-menu-768`). The title and the amount never run under it.
- **Read-only result lists (R4-24) are exempt:** the rows of the check dialog / sheet
  (`check-dialog-768`, `check-dialog-1024`) are evidence to compare, not records to act on, so they
  carry no «…» slot; their one action is the dialog's own buttons.
- **Read-only rows (R3-09):** a role that may not edit a record (JUNIOR on its own payments, `detail-readonly-1000`) keeps the «…» trigger, and its menu holds only the read actions: «Відкрити чек» (when the row has a receipt) and «Копіювати суму». A row with neither has no trigger, and its slot stays reserved.

- **Back** is a history entry pushed when the overlay opens; it closes **only the top layer**.
- **A dirty form asks first** on every exit above (Esc, back, scrim, swipe, ✕): «Вийти без
  збереження?» / «Введене в цій формі буде втрачено.» / «Вийти» / «Залишитися», focus on «Залишитися»
  (`sheet-dirty-close-375`; ≥ 640 the alert dialog). A clean form closes at once.
- **Maximum depth (R3-01, the one rule, every class):** two layers over the page (a panel and its
  confirm, a sheet and its picker). A third request **replaces the top layer** instead of stacking, and
  closing it returns to the layer it replaced. Phone: the check sheet replaces the form sheet, so the
  recreate confirm sits over one sheet (`confirm-recreate-375`, `save-failure-unknown-list-375`).
  ≥ 640: the check dialog sits over the panel; «Немає — створити ще раз» and «Є в списку — закрити
  чернетку» each **replace the check dialog** with their 440 px confirm, and «Скасувати» returns to the
  check dialog with focus on the button that opened the confirm (`confirm-recreate-768`,
  `confirm-recreate-1440`). The session alert is the one exception: it may sit over two layers, and its
  scrim covers the whole viewport, a non-modal panel included.
- **Every alert dialog (R3-02, R3-10):** ≥ 640 one width, 440 px; its `--scrim` covers the whole
  viewport, the sidebar, rail and a non-modal panel included, and **stacks above every panel, modal or
  not** (R4-02: the alert's scrim is the layer right under the dialog, above a modal panel's own scrim
  and the panel; `measure.mjs` `scrim` asserts on every frame and class that nothing but the dialog
  paints above it); everything under it is `inert`, so a field
  under it shows no focus ring and no caret: the dialog's initial-focus button carries the only ring
  (`alert-session-expired-768`, `alert-session-expired-1440`, `sheet-confirm-dialog-1024`,
  `signout-confirm-1440`).

### Forms (F0-22)

Columns follow the **container**, not the viewport (R1-07): one column below 560 px of container width (every side panel and every sheet; `sheet-panel-768`, `sheet-panel-1024` and `sheet-panel-1440` draw the canonical money form of §4 in one column, R3-03), two columns from 560 px (a full-page form, `formfield-768`, whose caption says the same), and columns of 360 px where the container holds three (`formfield-1440`).

### Lists, detail and selection (F0-24, F0-32)

- **Action slot by role and state:** the detail header and the row menu hold only what the viewer may
  do; a read-only viewer sees «Лише перегляд» in place of «Редагувати» / «Інші дії»
  (`detail-readonly-1000`).
- **One selection cue** everywhere: `--raised` fill + a 2 px `--primary` leading bar + `aria-current`
  (list pane) or `aria-selected` (table).
- **Wrap and truncation:** the row rule, §12.0.
- **Chips** that overflow scroll sideways with a 24 px end fade, so a cut chip reads as more.

### Drafts and money rows (F0-35, F0-36, F0-40, F0-41)

- **Precedence** (one pill slot, the row, the edit form): unknown > failed > in flight > armed > saved;
  an edit draft ranks the same as a create draft.
- **Amounts are signed** in rows, pills and accessible names; a sent draft shows its send time
  (`{time}` slot in the row, the pill and the name).
- **The pill + the pinned row are the visible error.** A failed save rolls back nothing that was
  shown as saved; no error toast. The frames are `save-failure-*`.
- **A success toast never covers the pill:** they stack in the same corner (shell-v2 §2).
- **An unknown record opened read-only keeps full contrast**; only the inputs are read-only.
- **Section totals** are per currency («−186,40 USD · −3 000,00 USDT»), never summed across currencies.
- **Page kill:** the dialog of §12 «Page kill dialog»; it names the marker's signed amount and time (F0-40, D-5); «Створити ще раз» prefills only that amount and currency.
- **Armed copy:** «Зберегти після завантаження чека» before the tap, «Збережеться {amount} після
  завантаження чека» after it (F0-41).
- **Pill format (R1-02):** line 1 is the state with the signed amount, nowrap; line 2 the detail. Armed «Збережеться −1 250,50 USD» / «62% · Відкрити чернетку»; saved «Збережено −…» / «Відкрити»; in flight «Зберігаємо −… USD…» / «Відкрити»; failed «Не збережено −…» / «14:32 · Відкрити»; unknown «Результат невідомий» / «−… USD · 14:32 · Відкрити»; several armed «Збережеться 2 транзакції» / «Після завантаження чеків · Відкрити»; two or more unresolved «2 потребують перевірки» / «Відкрити» (§5 holds the sentences).
- **Pinned row:** the signed amount alone on line 1 (nowrap); line 2 is `status · send time · type`, which wraps under the meta rule and never truncates its time; one tonal 44 px «Відкрити»; no icon tile on the phone. The leading bar and tint are `--destructive` (failed), `--warning` (unknown), muted (armed, in flight). Up to three rows; from four drafts, two rows and «Ще N чернеток · Показати». An armed row has no send time: «Збережеться після завантаження чека · Витрата».
- **Draft count on the create button (R2-11):** the count is the drafts that need attention (failed and unknown); armed and in-flight ones do not count. It rides on the dock button on a Фінанси phone and on the «+» elsewhere. One draws the plain red dot, two or more an 18 px numeric badge (`drafts-two-unresolved-375`, `drafts-four-collapsed-375`).
- **Create entry (D-8):** on a Фінанси phone the one create entry is the docked 48 px «Нова транзакція» primary button in its 64 px strip above the tab bar, in the bottom third of the screen (thumb zone); there is no top-bar «+» and no FAB there, and the list ends with strip + 16 of padding, so no amount is ever covered (`drafts-two-unresolved-375`, `listrow-draft-375`, `ptr-pulling-375`). The button carries the red dot with the count from two; its accessible name is «Нова транзакція», or with n drafts that need attention «Нова транзакція, {n} чернетка потребує уваги» (uk one: 1, 21, 31…), «…, {n} чернетки потребують уваги» (few: 2–4, 22–24…), «…, {n} чернеток потребують уваги» (many: 0, 5–20, 25–30…), a Lingui `plural` with the `uk` one / few / many forms and the `en` one / other forms. Tablet and desktop keep the rail «+» and the «Нова транзакція» header button. The other tabs keep their FAB and the quick-add «+». «+» never blocks (foundation §11).
- **Confirm titles name the signed amount:** «Створити −1 250,50 USD ще раз?», «Закрити чернетку −… USD?», «Видалити чернетку −… USD?».

### Desktop table (F0-37)

- **One loaded table template (R3-15):** every desktop page with a table draws the same frame: the toolbar (search, filter chips, the count), the column header, 40 px rows and the reserved «…» column. Banners stack above the toolbar; a toast or pill floats over it; the skeleton draws the real toolbar with a skeleton count (`banner-stack-1440`, `toast-undo-1440`, `skeleton-table-desktop`).
- Row states, top to bottom in `listrow-table-desktop`: default (with a status pill «Очікує»), hover,
  selected, keyboard focus, **write pending**. A pending row keeps its place, mutes its title and
  amount to `--muted-fg`, shows «Зберігаємо…» with a 13 px spinner after the title, and is
  `aria-busy="true"`; it cannot be opened for edit until it settles.
- **Sort (R2-33):** «Дата», «Опис» and «Сума» sort; «Тип», «Чек», the status and the «…» slot do not. A sortable header is a 44 px-high button (36 px at a fine pointer) with `aria-sort` on its `th` (`none` / `ascending` / `descending`); the active column shows an arrow after the label, the others show it on hover and focus only. One click sorts ascending, the next descending, the third restores the default («Дата ↓»); one column at a time, kept in the `sort` URL parameter (`sort=date:desc`) so a reload and a shared link keep it. The frame draws the default (`listrow-table-desktop`: the arrow on «Дата», `aria-sort="descending"`).
- **Number alignment (R2-10):** the amount is right-aligned and its currency code sits in a fixed 38 px slot at the end of the cell, left-aligned, so the digits of «−3 000,00 USDT» and «−12 400,00 UAH» end on one line and the codes (USD, UAH, USDT) never push them. The cell never truncates (R2-36).
- **Known limits in v2 (D-4, D-6):** the table has no inline cell edit (every edit opens the side panel) and no bulk select.
- The skeleton has the same columns and widths as the table (`skeleton-table-desktop`).
- Below 1032 px of main, «Проєкт» leaves the columns and rides in «Опис» as muted text; nothing is
  dropped. The status pill sits after the title in «Опис», never in its own column.

### Board (F0-38)

- Card meta takes two lines (role · project, then the date); it wraps, never truncates.
- **Column widths (the one rule; R4-14, R5-14).** Touch tablet (640–899): a fixed 290 px; two fit whole at
  768 and the third peeks under the end fade (`board-768`). Everywhere else: `minmax(220px, 280px)`, the
  columns share the width; when the stages do not fit at 220 px the board scrolls sideways with the edge
  fade (`board-1440`: six stages, five whole). So a name stays on one line (a focused card's «Етап» button
  may push a long name to a second line), the meta takes at most two lines, «·» binds to the item after it
  (NBSP: «Frontend · «Альфа»» never breaks inside) and a count badge is never cut.

### Tab-bar strip (F0-39)

Content under the translucent tab bar reads as motion only; nothing a user must read rests there, because
every phone scroller ends with the bottom padding of shell-v2 §2 (R3-12, the one formula).

### Strings (F0-27)

**Columns (R4-11).** `ID` is the row's stable key (kept when a row is edited or moved; a new row takes a
new ID, an ID is never reused). `Kind` is empty for copy a frame draws, or `interaction` for copy no

checks both directions: every drawn string is covered by a row with an `en` cell, and every token of a
row without `Kind` is drawn in some frame; and per row, uk and en have the same number of « · » parts
and the same placeholders.

`uk` is the source; `en` is written anew, not translated. Confirm titles never inflect a name: the name
stands in quotes or before a colon («Видалити транзакцію «Оренда офісу»?», «Олена Коваль: перевести в
«Найнято»?»). Stage vocabulary is one set everywhere. Glossary terms per `CONTEXT.md` (an Interview is

### Owner decisions (applied in r3)

The owner accepted these eight recommendations; each is now a rule with a drawn state. The ledger at the end of this file maps every id to its frame or rule.

- **D-1 — session expiry keeps form input.** Before the sign-in redirect the app persists the open form's draft on this device (field values, the selected receipt, the form id and the route); an armed money draft stays armed. After sign-in the app returns to the route, reopens the form with those values and shows a polite `role="status"` note «Введене відновлено» that never moves focus; «Очистити» drops the restored input and the local copy (`shell-v2/../form-restored-375`, `alert-session-expired-375`, `alert-session-expired-768`, `alert-session-expired-1440`). The copy is restored only for the same user, and is deleted on a save, on «Очистити», on sign-out (D-2) and after 24 hours. Tablet and desktop show the same note above the fields. The session alert says so: «Дані форми та вибраний чек збережуться на цьому пристрої й повернуться після входу.»
- **D-2 — sign-out and the impersonation return run the 401 loss check.** If an armed draft, a selected receipt, a dirty form or restore data exists, an `alertdialog` lists what would be lost (phone: the action sheet over the «Ще» sheet; tablet and desktop: a centred 440 px dialog), with «Вийти» (or «Повернутися») and «Залишитися»; initial focus is on «Залишитися» (`signout-confirm-375`, `signout-confirm-768`, `signout-confirm-1440`). With nothing to lose there is no dialog. The account-menu item is «Вийти з акаунта» / “Sign out”. Sign-out deletes the local restore data.
- **D-3 — notification delete is delayed 5 s with an undo toast.** The row leaves the list at once, the unread count drops, and the server delete is sent after 5 s unless «Скасувати» is pressed, which puts the row back in place. It is the same undo-toast primitive and the same pause rules as §5 (focus, hover, touch and a hidden page pause the timer; closing the page sends the delete) (`shell-v2/notifications-undo-375`, `shell-v2/notifications-undo-768`). **Where it sits (R3-17):** this toast belongs to the panel layer, not the page: in flow inside the phone sheet or the ≥ 640 popover, above the pinned «Усе, що чекає рішення» link (never over it), inside the panel's focus scope (Tab reaches «Скасувати» before it leaves a popover). Pressing it is not an outside press, so the popover stays open. After a delete, focus moves to the next row (the previous one when the last row went; the empty state's title when none is left); «Скасувати» returns focus to the restored row.
- **D-4 — no inline cell edit on the desktop table in v2.** A known limit (§12 Desktop table): every edit opens the side panel.
- **D-5 — the page-kill marker stores the signed amount and currency (local only).** Every page-kill dialog and the check sheet name the amount and the time on every class (`state-page-kill-375`, `alert-pagekill-sent-375`, `page-kill-768`, `page-kill-1440`, `check-sheet-boot-375`); «Створити ще раз» prefills only that amount and currency; the check sheet tags a later same-amount same-currency row «схожа · та сама сума», never «збіг».
- **D-6 — no table bulk select in v2.** A known limit (§12 Desktop table), matching the owner decision of no bulk select for users (#1392).
- **D-7 — the money form's project default is the active «Проєкт: X» filter on Фінанси.** It is shown prefilled in the defaults row and stays changeable (§4 Defaults, `shell-v2/quick-add-txn-project-375`).
- **D-8 — Фінанси create is a docked «Нова транзакція» button on the phone.** A 64 px strip (48 px primary button, 8 px padding, solid `--bg`, hairline top border) above the tab bar, in the bottom third; list bottom padding is strip + 16 so no amount is covered; the top-bar «+» is removed on Фінанси (one create entry); the pill and the toast stack above the dock at full width; the draft dot or count rides on the dock button (§12 Create entry; `drafts-two-unresolved-375`, `listrow-draft-375`, `ptr-pulling-375`, `upload-pill-armed-375`, `toast-pill-stack-375`). Tablet and desktop are unchanged.
