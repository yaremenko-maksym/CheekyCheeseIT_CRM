# job-sourcing-suggestion — дизайн-спека (degraded, retroactive gate closure)

**Статус:** design-gate закрывается пост-фактум — PR #493 (`feature/job-sourcing-slice1`) реализовал
экран без прохода через дизайнера ДО вёрстки (в задаче не был проставлен `## Design tier:`, дефолт
Tier 1 не сработал). Эта спека — Mode A текстовая документация + Mode B fidelity-аудит живого
экрана, задним числом закрывающая гейт по `.claude/rules/common/design-gate.md`.
**Design tier:** 1 (новый компонент/поток), фактически обработан как **degraded** — макета в
Claude Design нет (`fidelity: degraded`, см. PR-комментарий).
**Компоненты:** `apps/web/app/components/job-sourcing/JobSuggestionDialog.tsx`,
`apps/web/app/routes/_authenticated/interviews/index.tsx` (точка входа — кнопка «Подбор вакансий»).

## 1. Направление (frontend-design-direction)

- **Purpose:** HR/ADMIN подбирают внешние вакансии (DOU RSS) для конкретного синьора и продвигают
  очередь по одной карточке: посмотреть → открыть оригинал → отметить исход. Тот же экран сам синьор
  использует для своей собственной очереди — без права смотреть чужую.
- **Audience:** HR — несколько раз в неделю на человека в своей команде, сканирует заголовок/компанию/
  дату, решение принимается за секунды («подходит / не подходит»). SENIOR — эпизодически, тот же паттерн
  для себя. Оба уже знакомы с канбаном собеседований — диалог открывается с той же панели инструментов.
- **Tone:** `dense / quiet / scannable` — идентично остальному CRM (тёмная тема, карточка-диалог, а не
  отдельная страница; markdown-текст вакансии — единственный «читательский» блок, всё остальное —
  метаданные и три действия).
- **Memorable detail:** «одна вакансия за раз» вместо списка/таблицы — тот же паттерн очереди, что и
  колонки канбана рядом; ответ («Откликнулись»/«Не подходит») сразу подтягивает следующую, без
  промежуточного списка. Счётчик «Осталось: N» в шапке — единственная навигационная подсказка.
- **Constraints:** Tailwind v4, shadcn/ui/`CrmDialogContent`, русский UI, WCAG 2.2 AA,
  responsive 320/375/768/1024/1280/1440/1920, zero новых npm-пакетов сверх уже используемого
  `react-markdown` (добавлен этим PR намеренно — единственный безопасный способ рендерить вакансию с
  публичной доски без `dangerouslySetInnerHTML`).

## 2. Компонентный маппинг (переиспользовано 1:1, новых примитивов НЕ заведено)

| Заголовок/описание диалога       | `CrmDialogHeader` + `DialogTitle` + `DialogDescription` (`sr-only`)                                             |
| Скроллящееся тело                | `CrmDialogBody`                                                                                                 |

| Поле добавления исключения       | `Input` (`@/components/ui/input`)                                                                               |

`CrmDialogContent`.

резолвящиеся в CSS-переменные `@theme inline` (`apps/web/app/styles/globals.css`):

## 5. Markdown / security-hardening (влияет на визуал, поэтому фиксируется в спеке)

`descriptionMd` — недоверенный источник (публичная доска вакансий). Рендер сознательно НЕ показывает
изображения (`img: () => null`) и НЕ доверяет произвольным хостам в ссылках (`urlTransform` /
собственный компонент `a`, https-only, `rel="noopener noreferrer nofollow"`). Это одновременно
security-требование (см. security-review раунды 1-3 в PR) и design-решение: вакансия не должна тянуть
внешние изображения в наш authenticated origin. Дизайн-система это не нарушает — `prose prose-sm
dark:prose-invert` уже используется как паттерн для markdown-контента в других местах CRM.

## 6. Responsive-поведение (4 класса устройств)

Проверено вживую на реальном dev-стеке (не мок), Playwright, 07.08.2026 — см. §8 (fidelity-аудит).

| Класс         | Ширины теста  | Поведение                                                                                                                                                                                                                                                                                                                      |
| ------------- | ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Мобильный     | 320, 375, 393 | Диалог = 100% ширины вьюпорта (`w-full`, брейкпоинт `sm:` ещё не применяется). Футер `flex-col-reverse`: «Открыть оригинал» (`order-last`) визуально ПЕРВЫЙ сверху, затем «Не подходит», затем «Откликнулись» — все три full-width, `min-h-[44px]`. Панель исключений — поле ввода и кнопка «Добавить» в столбец (`flex-col`). |
| Планшет       | 768           | `sm:` активен → `maxWidth="sm:max-w-2xl"` пока не достигнут (768 < 672? нет, 672<768 — фактически на 768 диалог уже упирается в `672px` cap и центрируется) — измерено: ширина диалога 672px, футер — обычный ряд (`sm:flex-row`), кнопки `sm:w-auto`.                                                                         |
| Ноутбук       | 1024, 1280    | Диалог стабильно 672px по центру, без изменений относительно планшета.                                                                                                                                                                                                                                                         |
| Большой экран | 1440, 1920    | Диалог остаётся 672px (не растягивается на всю ширину — читаемая колонка текста вакансии), центрирован.                                                                                                                                                                                                                        |

Горизонтального overflow (`document.documentElement.scrollWidth > clientWidth`) НЕ обнаружено ни на
одной из 7 протестированных ширин — ни в пустом состоянии, ни с реалистичным длинным описанием
(длинный URL, неразрывный «хэштег»-токен, длинный заголовок вакансии).

## 8. Fidelity-аудит (Mode B, живой стек, 07.08.2026)

Референса `design.png` нет (Claude Design не запускался на эту задачу) → аудит идёт против этой спеки
и `docs/design/foundation.md` (`fidelity: degraded`, причина: задача ушла в реализацию без design-tier
gate). Полный отчёт с числами и скриншотами — комментарий в PR #493. Кратко:

- **Проверено конкретное подозрение код-ревьюера** («диалог 858px в вьюпорте 393px», несовместимое с
  зелёным тестом на 320) — измерение живого (немутированного) компонента на 320/375/393/768/1024/1280/1440/1920
  показало **отсутствие overflow на всех восьми ширинах** (dialog width == viewport width на мобильных,
  672px на ≥768). Число 858px — из PR-комментария код-ревьюера: получено **мутационным тестированием**
  (`className="min-w-[900px]"` инъекция в `CrmDialogContent`) для доказательства, что ассерт
  `documentElement.scrollWidth > clientWidth` в `job-sourcing-mobile.spec.ts:253-260` не ловит overflow
  `position: fixed`-элемента — это находка про **качество теста** (зона AutoTest/Coder, не про реальный
  визуальный дефект). В текущем коде такого overflow нет.
- **Найдено и исправлено (cosmetic, в рамках этого прохода):** кнопка удаления ручного исключения была
  20×20px — ниже минимума WCAG 2.5.8. Правка: `h-5 w-5 min-h-[20px] min-w-[20px]` →
  `h-6 w-6 min-h-[24px] min-w-[24px]` (`JobSuggestionDialog.tsx`, единственная строка). Проверено:
  ESLint чисто, визуально — правка не ломает раскладку чипа.
- **Найдено и НЕ исправлено (функциональный баг, не косметика — оставлено кодеру):** SENIOR, открывая
  свою собственную очередь, не может добавить ручное исключение через «Добавить» — кнопка визуально
  активна, но `ExclusionsPanel.submit()` (`JobSuggestionDialog.tsx:116`) молча возвращается на
  `!seniorId`, а для self-view `seniorId` проп — намеренно `undefined` (см.
  `interviews/index.tsx`: `seniorId={isSenior ? undefined : effectiveSeniorId}`). Ни ошибки, ни тоста —
  запрос на бэкенд не уходит вообще (подтверждено логом API: 0 POST-запросов при клике). Для HR/ADMIN
  (передают явный `seniorId`) кнопка работает штатно — воспроизведено. «Удалить» на ручном исключении
  для SENIOR работает (не завязано на `seniorId` на клиенте) — асимметрия усиливает впечатление бага, а
  не намеренного ограничения.

## 9. Edge cases

- Длинный заголовок вакансии — переносится по словам (`h2` без доп. класса, браузер по умолчанию
  переносит по пробелам), проверено на 320px с 80-символьным заголовком.
- Длинная непрерывная строка в описании (URL с query-параметрами, «хэштег» без пробелов) — переносится
  внутри `prose` блока (`break-words` на контейнере), overflow не создаёт.
- Компания/локация без даты публикации — опциональные `·`-сегменты в параграфе рендерятся условно,
  вёрстка не ломается (проверено структурой JSX, `current.posting.location &&` / `publishedAt &&`).
- Пустая очередь при активной панели исключений — оба блока сосуществуют, скролл работает.

## 10. Известные ограничения (вне зоны дизайнера)

- Функциональный баг §8 (SENIOR self-create exclusion) — требует правки прокидывания `seniorId` в
  `apps/web/app/routes/_authenticated/interviews/index.tsx` / `use-job-sourcing.ts`, зона Coder.
- Тестовый гейт §8 (мёртвый ассерт в `job-sourcing-mobile.spec.ts:253-260`) — зона AutoTest/Coder,
  описано детально в PR-комментарии код-ревьюера, не дублируется здесь.
