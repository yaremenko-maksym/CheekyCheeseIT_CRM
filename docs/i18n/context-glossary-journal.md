## Формы `uk`/`en` (этап 3, волна a — `web-core`, задаёт этот PR)

Продукт двуязычный: исходный текст в коде — `uk` (`sourceLocale`), `en` — второй оригинал в том же
PR. Ниже — канонические формы терминов этой волны (первый PR стадии 3 их заводит, дальше волны
только ссылаются). Разнобой в каталоге на один термин (`проект`/`проєкт`, три слова для дохода,
`Ставка` вместо `Частка`) — находка `copy-reviewer` (copy review круга 1, PR #700).

| Приглашение (сущ., для пользователя) | запрошення              | invitation            | `invite` как существительное — только глагол («invite the person»); допущение A1, copy review круга 1, PR #707                                            |

Апостроф — `’` (U+2019) везде, не `'` (U+0027) и не `ʼ` (U+02BC) — решение copy-review круга 2
(COPY-L-25, PR #700): на момент этого PR в `main` уже 126 записей с U+2019 (#699/#701), это и есть
фактический стандарт каталога, а не документированный ранее U+0027. Многоточие — `…` (один символ),
не `...`. `en`-типографика — типографские кавычки `“…”` (U+201C/U+201D), не прямые `"` и не ёлочки `«…»`. `uk` — ёлочки `«…»`.

`en`-отказы («не удалось сделать X») — канон **«Could not …»**, не «Couldn't …» — решение
copy-review круга 1 PR #706 (COPY-L-2): на момент этого PR этот PR добавляет 23 новых «Could not»
против 6 существующих в `main`, «Couldn't» — 8, к тому же с прямым апострофом U+0027, а не
типографским (см. выше). Новый текст пишется как «Could not …»; существующие 8 «Couldn't» —
отдельная задача, не переписываются попутно.
