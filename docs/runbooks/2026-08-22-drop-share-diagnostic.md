# Диагностика: не посчитана ли доля компании у дропов по проценту синьора

**Статус:** диагностика, **не починка**. Ничего не меняет.
**Кто выполняет:** владелец (у ассистента нет доступа к прод-БД).
**Пункт бэклога:** 4 (система А).

---

## Что именно проверяем

Раньше в интерфейсе был **один общий диалог** для приходов. Он считал долю компании
по проценту **синьора** — и делал это даже тогда, когда приход был от **дропа**
(подтверждено чтением кода при ревью #445).

У синьора и дропа проценты разные. Значит, если дроп хоть раз проводил приход через тот
диалог, компания удержала **не ту долю**: сумма разошлась с тем, что должно было быть по
проценту дропа.

Сегодня код так больше не считает — есть отдельный резолвер доли дропа
(`apps/api/src/finance/drop-share-resolver.ts`, `resolveDropShare`), и каждая строка
несёт снимок своего процента. **Вопрос только в исторических строках**: попал ли кто-то
под старое поведение до того, как его починили.

## Что запрос НЕ делает

- не меняет ни одной строки;
- не пересчитывает суммы;
- не говорит, какая сумма правильная.

Он отвечает ровно на один вопрос: **пострадали мы вообще или нет.**

## Как читать результат

| Результат           | Что это значит                                                     | Что делать       |
| ------------------- | ------------------------------------------------------------------ | ---------------- |
| **Пусто (0 строк)** | Через тот диалог дропы не платили. Проблема нас не коснулась.      | Закрыть пункт 4. |
| **Есть строки**     | Столько-то приходов дропа несут процент синьора — суммы разошлись. | См. ниже.        |

Если строки есть — **не чините сразу**. Пришлите вывод мне: пересчёт делается адресно, потому
что у разных путей отличается семантика суммы (где-то записано «до удержания», где-то «после»),
и одной формулой это не закрыть. Второй запрос ниже даёт только **порядок величины**, чтобы
понимать масштаб — это не основание для правки данных.

## Как запустить

Подключение к прод-БД идёт через контейнер на VPS (SSH-доступа к базе напрямую нет):

```bash
docker exec -i <имя-контейнера-postgres> psql -U crm_user -d crm_db
```

Затем вставить запросы ниже. Либо целиком файлом:

```bash
docker exec -i <имя-контейнера-postgres> psql -U crm_user -d crm_db -v ON_ERROR_STOP=1 < prod-queries.sql
```

Флаг `-v ON_ERROR_STOP=1` тут не критичен (запросы читающие), но приучаться стоит: без него
psql возвращает «успех» даже когда SQL упал.

## Запрос 1 — есть ли пострадавшие

```sql
SELECT
  t.id,
  t.type,
  t.status,
  t.amount,
  t.currency,
  t.senior_share_percent AS pct_stamped_senior,
  t.drop_share_percent   AS pct_stamped_drop,
  u.display_name         AS drop_name,
  u.drop_share_percent   AS drop_pct_now,
  t.created_at
FROM transactions t
JOIN users u ON u.id = COALESCE(t.receiver_id, t.recipient_id, t.sender_id)
WHERE u.role = 'DROP'
  AND t.senior_share_percent IS NOT NULL
ORDER BY t.created_at;
```

**Логика:** ищем строки, где получатель/отправитель — дроп, но на строке стоит снимок
процента **синьора** (`senior_share_percent IS NOT NULL`). У честно проведённого прихода
дропа этого поля быть не должно — там должен стоять `drop_share_percent`.

Колонка `drop_pct_now` показывает, какой процент у этого дропа **сейчас** — пригодится, чтобы
понять, насколько велика разница.

## Запрос 2 — только если первый вернул строки

```sql
SELECT
  t.id,
  t.type,
  t.amount                                            AS amount_now,
  t.senior_share_percent                              AS pct_stamped_senior,
  COALESCE(u.drop_share_percent, 5)                   AS pct_drop,
  round(t.amount * COALESCE(u.drop_share_percent, 5)::numeric
        / NULLIF(t.senior_share_percent, 0)::numeric, 6) AS amount_if_drop_pct,
  u.display_name                                      AS drop_name
FROM transactions t
JOIN users u ON u.id = COALESCE(t.receiver_id, t.recipient_id, t.sender_id)
WHERE u.role = 'DROP'
  AND t.senior_share_percent IS NOT NULL
ORDER BY t.created_at;
```

**Что показывает:** рядом с текущей суммой — прикидку, сколько было бы по проценту дропа.
Разница между `amount_now` и `amount_if_drop_pct` и есть масштаб расхождения.

**Ещё раз: это ориентир, а не готовый пересчёт.** Подставлять `amount_if_drop_pct` в базу
нельзя — у разных путей отличается, включена доля в сумму или вычтена из неё.
