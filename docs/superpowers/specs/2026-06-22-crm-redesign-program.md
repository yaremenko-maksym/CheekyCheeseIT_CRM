## 1. Цель

Владелец: «постепенный дизайн-рефактор всего проекта — полностью нарисовать дизайн CRM с нуля, учитывая
весь текущий функционал; дизайн должен быть правильный и профессиональный на всём проекте; разбить на
фазы и имплементировать.»

То есть: **профессиональный редизайн каждого экрана/модалки CRM**, на едином визуальном языке, с
сохранением **всего текущего функционала 1:1** (редизайн = визуал + UX, НЕ изменение бизнес-логики),
раскатанный **фазами**, designer-first (владелец апрувит макет до кода).

## 2. Почему redesign-from-scratch, а не mirror (architecture decision)

Зеркалирование существующего UI через AI-генерацию Claude Design — низкая ценность (CD «перерисует»
приближённую копию того, что уже есть точно в коде) + высокое трение (file_upload принимает только
session-shared файлы, нативный пикер недрайвится). **Сила Claude Design — генерация нового/изменённого
дизайна.** Поэтому:

- **Вход генерации = текстовый функц-бриф** (описание экрана + весь функционал + наши токены/компоненты),
  а НЕ загрузка скриншота → **снимает блокер**: поле «describe what you want to make» драйвится через
  Chrome MCP автономно (текст, без upload).
- Захваченные faithful-скриншоты (`docs/design/screens/<domain>/assets/`) + чтение кода = **референс
  функционала** для брифа (что должно быть на экране), не выход.

## 3. Повторяемый цикл на экран (designer-first dev-loop)

```
(0) Foundation готова (Phase 0): единый визуальный язык на системе CheekyCheeseIT CRM
(1) Функц-бриф: оркестратор из кода/скриншотов выписывает ВЕСЬ функционал экрана (фичи, данные,
    состояния, роли, edge-cases) + design-direction (Phase 0) + наши токены/компоненты
(2) Генерация в Claude Design (Chrome MCP, текст-бриф, system=CheekyCheeseIT CRM) → профессиональный
    дизайн → рефайн через conversation
(3) Экспорт-артефакт в репо: docs/design/screens/<domain>/<screen>.md (coder-spec) +
    assets/<screen>/{design.html, *.png} + запись в docs/design/screens/INDEX.md (status captured)
(4) ВЛАДЕЛЕЦ визуально апрувит макет → реестр approved (ГЕЙТ: без апрува кодер не диспатчится)
(5) Coder реализует в apps/web по артефакту (наши компоненты/токены; функционал сохраняется 1:1)
(6) ui-ux-designer Mode B fidelity-аудит (live vs design.png) → code-review → User Testing → «мерджим»
    → реестр implemented
```

Машинерия уже в main (#279): `design-gate.md` (3-tier + энфорсмент), ui-ux-designer Mode E (reconciliation)

- Mode B (fidelity), `claude-design-workflow` skill, артефакт-контракт. Переиспользуем как есть.

## 4. Принципы

- **Блоки + данные 1:1 (КРИТИЧНО):** редизайн = **рестайл существующих блоков** — те же блоки, те же
  лейблы, то же наполнение данными, что и на РЕАЛЬНОМ экране. Меняем ТОЛЬКО визуал / отступы / иерархию /
  расположение по канонам UI/UX. **НИЧЕГО нового не добавлять** — никаких новых кнопок/ссылок/карточек/
  KPI/виджетов, не дублировать логику. Не удалять фичи, не трогать бизнес-логику/API/RBAC.
  **Capture-grounded бриф:** перед генерацией оркестратор снимает РЕАЛЬНЫЙ экран (Playwright :3100) и
  перечисляет в брифе его точные блоки/лейблы/данные + явный запрет «add nothing not listed». (Урок
  2026-06-22: свободный бриф → CD напридумывал KPI/кнопки/«Доход», которых на реальном дашборде нет.)
- **Единый язык:** Phase 0 задаёт layout-сетку, плотность, type-scale, семантику цвета, motion, a11y (WCAG 2.2 AA),
  паттерны компонентов. Все фазы следуют ему → консистентность.
- **Профессионально, не AI-slop:** ui-ux-designer Mode C ловит generic-паттерны; цель — dense SaaS operations tool.
- **Порядок фаз:** от репрезентативного/низкорискового к money/RBAC-тяжёлому.
- **Гейт владельца:** каждый экран — `approved` в реестре до кода; merge — только явное «мерджим».
- **Реестр** `docs/design/screens/INDEX.md` — карта прогресса (captured→approved→implemented).

| **1** | **Interviews** (канбан + 5 модалок)                                       | Пилот; функц-референс уже захвачен (`docs/design/screens/interviews/assets/`).   |

## 6. Failure modes & fallbacks

- **Генерация из текста в CD не драйвится через Chrome MCP** → fallback: оркестратор отдаёт бриф,
  владелец генерит/рефайнит в браузере, оркестратор подхватывает экспорт. (Проверяется в Phase 0 Step 1.)
- **Дрейф от текущего функционала** → бриф перечисляет функционал как чек-лист; Mode B + code-review сверяют,
  что ни одна фича не потеряна.
- **CD недоступен / лимит** → ui-ux-designer Mode A текстовая спека; PR помечен `design-gate: degraded`.
- **Объём** → строго фазами; не начинать следующую фазу, пока предыдущая не `approved`+смержена (или явный параллельный дисптач владельцем).

## 7. Вне scope (YAGNI)

- Изменение бизнес-логики / API / схемы БД (только визуал+UX).
- `apps/landing` (отдельно, при редизайне лендинга).
- Авто-CI-триггер дизайна (CD интерактивный).
- Faithful-зеркалирование существующего (заменено редизайном).
