# Интернационализация CRM — дизайн (uk + en, Lingui 6)

**Дата:** 2026-09-19. **Статус:** согласовано с владельцем (решения зафиксированы в §1), ждёт
планов этапов. **Область:** `apps/web`, `apps/api`, `packages/shared`, тесты и правила проекта.
Лендинг (`apps/landing`) уже пятиязычный и здесь не трогается.

## 2. Цель и не-цель

**Цель.** Любой сотрудник видит CRM, письма и счета на своём языке (`uk` или `en`), переключает
его в профиле, и ни одна поверхность продукта не содержит русского текста. Покрытие переводов
проверяется механически в CI, а не глазами.

**Не-цель.** Перевод пользовательских данных (названия проектов, причины отказа, легенды, тексты
вакансий — у них свой механизм), контрактов (уже украинские), Signal-бота, телеметрии и логов
(остаются английскими по `russian-language.md`), а также добавление третьего языка. Архитектура
не должна этому мешать, но ничего под это не строится.

## 4. Архитектура

### 4.1. Локаль

- `users.locale` — enum `uk | en`, `NOT NULL DEFAULT 'uk'`. DDL — только через `deploy.yml`
  (`apps/api/drizzle/manual/`, идемпотентно, `check-prod-ddl-wiring.py`). Задаётся в мастере
  создания пользователя и меняется в профиле (вкладка «Настройки»); `/auth/me` отдаёт `locale`.
- До входа (страница входа, письмо-приглашение без учётки): cookie `pref_locale` (та же, что на
  лендинге) → `Accept-Language` → `uk`.
- Письма, уведомления и PDF рендерятся по `locale` **получателя** из `users`, не отправителя.
- Формат дат, чисел и денег — одна функция на каждый вид в `packages/shared/i18n/format.ts`
  поверх `Intl` с локалью из контекста; прямые `toLocaleString('ru-RU')` и `date-fns` с
  фиксированной локалью уходят.

### 4.2. Каталоги и сборка

- Источник истины — `packages/shared/i18n/locales/{uk,en}/messages.po`; `lingui compile`
  кладёт рядом `messages.ts`. Один каталог на три потребителя: веб (`@lingui/react`, Vite-плагин,
  макросы `t`/`Trans`/`msg`/`plural`), API (`@lingui/core`, `i18n.activate(locale)` на рендер
  письма или PDF), shared (дескрипторы `msg` без активации).
- Исходный текст в коде — **украинский**; id сообщения — хеш от текста (дефолт Lingui ≥4), явные
  id только для строк без текста (коды ошибок, §4.3).
- `lingui.config.ts` в корне монорепо; `sourceLocale: 'uk'`, `locales: ['uk','en']`,
  `catalogs` по трём пакетам. Версии — в `version-pins.md` (пакеты `@lingui/*` одной версией).

### 4.3. Ошибки API

- Конверт ошибки: `{ statusCode, code, params?, message }`. `code` — стабильный идентификатор
  (`CONTRACT_SIGN_IMPERSONATION`, `PROJECT_NOT_IN_TEAMS`, …), `params` — подстановки без PII,
  `message` — английская строка для логов и клиентов без каталога (обратная совместимость).
- `apps/api`: `throw new ForbiddenException({ code, params })` через тонкий хелпер
  `apiError(code, params)`; фильтр исключений формирует конверт. Реестр кодов —
  `packages/shared/src/schemas/api-errors.ts` (enum + Zod-схема конверта + `msg`-дескриптор
  на каждый код, чтобы `lingui extract` видел строки).
- Клиент: `getApiErrorMessage` ищет `code` в каталоге, иначе — общий текст «Не вдалося
  виконати дію»; коды, требующие подсказки «что делать», несут её в тексте каталога.
- Zod-сообщения в `packages/shared` (`message: '…'`) → коды через тот же реестр; клиентские
  формы рендерят их по коду.

### 4.4. Уведомления и письма

- `notifications`: `title`/`body` перестают быть источником текста для новых типов. Показ
  (попап, `/pending`, вкладка, письмо) рендерит текст по `type` + `data` через каталог по локали
  зрителя/получателя. Существующие строки остаются как запасной текст для legacy-типов.
- `notification-email-copy.ts` — шаблоны через `t`/`plural` в каталоге; крон активирует локаль
  получателя перед рендером; тема письма — тоже из каталога.
- `NOTIFICATION_TITLES` и подобные `Record<Type, string>` в shared → `Record<Type, MessageDescriptor>`.

### 4.5. PDF счетов

`invoice-pdf.service.ts` рендерит по локали получателя; текстовые константы — из каталога. Шрифт
PDF обязан содержать `і ї є ґ` (проверить `pdf.constants.ts`, при необходимости заменить).
Контракты не трогаются.

### 4.6. Веб

- Провайдер `I18nProvider` в `__root.tsx`; локаль из `/auth/me`, до входа — из cookie.
- Переключатель: вкладка «Настройки» профиля + поле в мастере создания.
- Каждый модуль мигрирует целиком в одном PR (§7): литералы → макросы, длины en/uk на 320
  проверяет дизайнер (design-gate Tier 2), тексты обоих языков — copy-reviewer.

## 5. Гейты и наблюдаемость

| Гейт                                                     | Где                                  | Режим                                      |
| -------------------------------------------------------- | ------------------------------------ | ------------------------------------------ |
| `lingui/no-unlocalized-strings` (`eslint-plugin-lingui`) | `apps/web`, `packages/shared`        | этапы 2–4: warning; этап 6: error          |
| `lingui extract --clean` + 0 непереведённых `en`         | CI, required-чек «Typecheck…»        | с этапа 2 для мигрированных модулей        |
| Guard на русские буквы `[ыЫэЭъЪёЁ]` в продуктовом коде   | `scripts/devops/check-no-russian.sh` | этап 6: error (этих букв нет в украинском) |
| Воркфлоу 8 «Language / locale-leak sweep»                | по запросу                           | после этапа 6 — аудит покрытия, не утечек  |
| `copy-reviewer` на каждый PR с каталогами                | review                               | вердикт по `uk` и по `en` отдельно         |

## 6. Правила и документы проекта, которые меняются

- `.claude/rules/common/russian-language.md`: русский — язык общения с владельцем, PR-обсуждений
  и отчётов агентов; **продукт** (UI, письма, PDF) — `uk`/`en`; запрет украинского в продукте
  снимается. Логи — английский, как и было.
- `CONTEXT.md`: глоссарий получает колонки `uk` и `en` для каждого термина (источник для
  каталогов и для copy-reviewer).
- `.claude/agents/copy-reviewer.md`, `.claude/skills/copywriting`: два языка CRM, рубрика «два
  оригинала» распространяется на CRM.
- `.claude/rules/common/version-pins.md`: пины `@lingui/*`.
- `.claude/agents/workflow-registry.md` №8: переход в translation-coverage.
- `docs/runbooks/human-only.md`: ничего нового для владельца (локаль — поле в профиле).

## 7. Этапы (каждый — своя спека-приложение и план; PR по модулям)

1. **Аудит (бэклог 136 + воркфлоу 8).** Read-only, по срезам: каркас/навигация, команда и
   профиль, проекты и собеседования, финансы, документы/уведомления/pending, API-исключения,
   shared. На выходе по срезу: дефекты поведения текста (ошибка без «что делать», английские
   утечки, расхождения с глоссарием) и **опасности миграции** — склейка строк, ручные
   множественные формы, родовые окончания, текст в константах и `Record`. Результат —
   `docs/architecture/2026-09-19-crm-i18n-audit.md`.
2. **Фундамент.** Lingui и конфиг, `packages/shared/i18n` (пустые каталоги + `format.ts`),
   `users.locale` + DDL, `/auth/me`, провайдер и переключатель, конверт кодов ошибок и реестр,
   `getApiErrorMessage` по коду, ESLint-правило в warning, правки правил (§6). Ноль переведённых
   экранов — но всё готово, чтобы модуль мигрировал одним PR.
3. **Веб по модулям** волнами ≤3 PR: (a) каркас, навигация, вход, общие компоненты `ui`/`layout`,
   `lib`/`hooks`; (b) команда, пользователи, профиль, онбординг; (c) проекты, собеседования,
   вакансии; (d) финансы, статистика, счета; (e) документы, уведомления, `/pending`, routing.
4. **API и shared.** Исключения → коды (289), Zod-сообщения, заголовки уведомлений при показе,
   письма uk/en.
5. **PDF счетов** по локали получателя.
6. **Закрытие.** ESLint-правило в error, guard на русские буквы, `extract --clean` обязателен,
   удаление остатков, воркфлоу 8 как аудит покрытия, снятие временных исключений.

Этапы 3 и 4 могут идти параллельно волнами; 5 — после 4 (общий каталог и активация локали).

## 8. Тестирование

- Unit/E2E: элементы ищутся по `data-testid` и ролям; текст в ассертах берётся из каталога `uk`
  (импорт скомпилированного сообщения), не литералом. Правило дополняется в
  `.claude/skills/playwright-patterns`.
- Каждый модульный PR: unit web/api/shared, интеграционные затронутых модулей, E2E-спеки модуля
  на живом стенде, гейт мутаций на диффе, скриншоты 320/1440 в обоих языках.
- Письма: `notification-email-copy.spec.ts` — снапшот темы и тела на `uk` и `en`.
- PDF: снапшот-тест текста счёта на обеих локалях + проверка глифов шрифта.

## 9. Риски

- **Объём.** ~6 500 строк и ~500 тестовых файлов. Снижение: модульные PR, мутационный гейт на
  диффе, ESLint-правило ловит пропуски до ревью.
- **Смешение языков в переходный период.** Пока модуль не мигрирован, он показывает русский.
  Снижение: порядок волн от каркаса к периферии; guard на русские буквы включается только в
  этапе 6.
- **Уведомления в базе.** Старые строки останутся русскими до истечения; рендер по типу
  закрывает это для всего нового.
- **Длина английского и украинского.** Украинский длиннее английского на 15–30 %: дизайнер
  проверяет 320 на обоих языках в каждом модульном PR.

## 10. Проверка готовности вехи

- В `apps/web`, `apps/api`, `packages/shared` guard на русские буквы молчит.
- `lingui extract --clean` даёт 0 непереведённых ключей `en`.
- Сотрудник с `locale = en` видит интерфейс, письмо и счёт на английском; с `uk` — на
  украинском.
- `copy-reviewer` выдал `PASS` на обоих каталогах.
