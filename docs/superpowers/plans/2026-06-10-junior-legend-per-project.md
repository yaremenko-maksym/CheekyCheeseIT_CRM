# Legend → Per-Project Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:test-driven-development for each task. Steps use checkbox (`- [ ]`) syntax for tracking. Backend tests are MANDATORY (not mocked E2E) — every RBAC branch gets a real guard test (403/200).

**Goal:** Move the legend from per-user (`legends.userId` UNIQUE, viewed on the user profile) to **one-per-project** (`legends.projectId` UNIQUE, viewed in the project context), add a journal (`legend_entries`) the junior appends to, and enforce the reversed RBAC (subject excluded; ADMIN/HR-of-team/active-junior view **and** edit).

**Architecture:** A project's legend is the single client-facing persona presented on that project. Behind it stands the drop (on drop-projects) or the senior (otherwise) — but that subject is a backend detail derived from `projects.dropId ?? projects.seniorId`; the junior always sees it labelled «синьор», and the drop is never named. Both `seniorId` and `dropId` users are **excluded** from viewing. The `legends` table is **empty in production** (verified `SELECT count(*) FROM legends = 0`), so the migration is a clean DDL change with **no data transform**.

**Tech Stack:** NestJS 11 + Fastify, Drizzle ORM (PostgreSQL), Zod v4 (`@crm/shared`), React + Vite + TanStack Query/Router. Vitest for backend unit/integration.

**Scope boundary:** This plan is the **foundation** (data model + RBAC + endpoints + a _functional_ frontend that renders the legend in the project context). The full junior UX redesign (hub, polish, placement refinement) is Phase 2 — out of scope here. Finance masking (rate/currency) and senior↔senior invisibility are a **separate** sibling plan, not this one.

## RBAC contract (authoritative — every task references this)

`canViewLegend(viewer, project)` where `project` has `{ seniorId, dropId, archivedAt }`:

| Viewer                                              | Result                       |
| --------------------------------------------------- | ---------------------------- |
| `ADMIN`                                             | **true**                     |
| viewer.id === project.seniorId                      | **false** (subject excluded) |
| viewer.id === project.dropId                        | **false** (subject excluded) |
| `HR` sharing an active team with `project.seniorId` | **true**                     |
| `HR` not sharing a team                             | false                        |
| `JUNIOR` active `project_member` of `project.id`    | **true**                     |
| `JUNIOR` not on the project                         | false                        |
| `ACCOUNTANT`                                        | false                        |
| any other `SENIOR`/`DROP`                           | false                        |

**Edit access == view access** (`PUT` legend and `POST` entry use the same check). Archived projects: legend still readable by ADMIN/HR; treat `archivedAt` as non-blocking for read (matches old behaviour — junior membership check already excludes archived via `project_member` leftAt, but ADMIN/HR keep access).

## Task 1: Schema — `legends` per-project + `legend_entries`

**Files:**

- Modify: `apps/api/src/database/schema.ts` (the `legends` block at ~line 829 + `legendsRelations` at ~1071; `users.legend` relation at ~929)

**Design (Drizzle):**

```ts
// One legend per project — the client-facing persona presented on that project.
export const legends = pgTable('legends', {
  id: uuid('id').primaryKey().defaultRandom(),
  projectId: uuid('project_id')
    .notNull()
    .unique()
    .references(() => projects.id, { onDelete: 'cascade' }),
  fullName: text('full_name').notNull(),
  dateOfBirth: text('date_of_birth'),
  address: text('address'),
  presentedRole: text('presented_role'), // «должность» которую презентуем
  presentedStack: text('presented_stack'), // стек/технологии персоны
  backstory: text('backstory'), // легенда-нарратив
  hobbies: text('hobbies'),
  notes: text('notes'),
  createdAt: timestamp('created_at', { withTimezone: true }).notNull().defaultNow(),
  updatedAt: timestamp('updated_at', { withTimezone: true }).notNull().defaultNow(),
})

// Journal — junior appends новую информацию, узнанную на проекте.
export const legendEntries = pgTable('legend_entries', {
  id: uuid('id').primaryKey().defaultRandom(),
  legendId: uuid('legend_id')
    .notNull()
    .references(() => legends.id, { onDelete: 'cascade' }),
  authorId: uuid('author_id')
    .notNull()
    .references(() => users.id),
  text: text('text').notNull(),
  createdAt: timestamp('created_at', { withTimezone: true }).notNull().defaultNow(),
})
```

Relations: replace `legendsRelations` (`user` → drop; add `project: one(projects, …)` + `entries: many(legendEntries)`); add `legendEntriesRelations` (`legend: one(legends)`, `author: one(users)`). **Remove** the `users.legend` one-to-one relation (~line 929) — legend is no longer per-user.

- [ ] Edit `schema.ts`: replace the `legends` table, add `legendEntries`, fix relations as above.

## Task 3: Shared Zod schemas

**Design:**

```ts
export const legendEntrySchema = z.object({
  id: z.string().uuid(),
  legendId: z.string().uuid(),
  authorId: z.string().uuid(),
  authorName: z.string(), // joined display name for UI
  text: z.string(),
  createdAt: z.string(), // ISO
})
export type LegendEntry = z.infer<typeof legendEntrySchema>

export const legendSchema = z.object({
  id: z.string().uuid(),
  projectId: z.string().uuid(),
  fullName: z.string(),
  dateOfBirth: z.string().nullable(),
  address: z.string().nullable(),
  presentedRole: z.string().nullable(),
  presentedStack: z.string().nullable(),
  backstory: z.string().nullable(),
  hobbies: z.string().nullable(),
  notes: z.string().nullable(),
  entries: z.array(legendEntrySchema),
  createdAt: z.string(),
  updatedAt: z.string(),
})
export type Legend = z.infer<typeof legendSchema>

export const upsertLegendSchema = z.object({
  fullName: z.string().min(1, 'Имя обязательно'),
  dateOfBirth: z.string().nullish(),
  address: z.string().nullish(),
  presentedRole: z.string().nullish(),
  presentedStack: z.string().nullish(),
  backstory: z.string().nullish(),
  hobbies: z.string().nullish(),
  notes: z.string().nullish(),
})
export type UpsertLegendDto = z.infer<typeof upsertLegendSchema>

export const addLegendEntrySchema = z.object({
  text: z.string().min(1, 'Текст обязателен').max(5000),
})
export type AddLegendEntryDto = z.infer<typeof addLegendEntrySchema>
```

## Task 4: `LegendsService` rewrite (project-scoped + RBAC) — TDD

**Files:**

- Modify: `apps/api/src/legends/legends.service.ts`
- Create: `apps/api/src/legends/legends.service.spec.ts`

**Service surface:**

```ts
async getLegend(viewer: SessionUser, projectId: string): Promise<Legend>     // 404 if none
async upsertLegend(viewer: SessionUser, projectId: string, dto: UpsertLegendDto): Promise<Legend>
async addEntry(viewer: SessionUser, projectId: string, dto: AddLegendEntryDto): Promise<Legend>
private async canAccess(viewer, project): Promise<boolean>   // implements the RBAC contract table
```

- Load the project first (`{ id, seniorId, dropId }`) → 404 `Проект не найден` if missing.
- `canAccess` implements the contract table above. Reuse the team-share query shape from the old `hrCanViewLegend` (HR shares an active `team_members` row with `project.seniorId`).
- `getLegend` returns the legend joined with `entries` (ordered `createdAt ASC`) + each entry's `authorName` (join `users.displayName`). 404 if no legend row.
- `upsertLegend` — atomic upsert on `legends.projectId` (`onConflictDoUpdate`), mirroring the old race-safe pattern.
- `addEntry` — RBAC check, then INSERT entry with `authorId = viewer.id`; return the refreshed legend (with entries). 404 if no legend exists yet (entries require a legend).

**TDD — write `legends.service.spec.ts` FIRST.** Mock `DatabaseService`. Cover the full RBAC matrix for all three methods. Minimum cases (each its own `it`):

```
canAccess:
  - ADMIN → true
  - viewer === project.seniorId → false
  - viewer === project.dropId → false
  - HR sharing team with senior → true
  - HR not sharing → false
  - JUNIOR active member → true
  - JUNIOR not member → false
  - ACCOUNTANT → false
  - other SENIOR → false
getLegend: 404 when project missing; 404 when no legend; ForbiddenException when !canAccess; returns parsed Legend with entries when allowed
upsertLegend: Forbidden when !canAccess; creates then updates (upsert) on same projectId
addEntry: Forbidden when !canAccess; 404 when no legend; appends with authorId=viewer.id
```

- [ ] Write the spec (all cases above, real assertions).
- [ ] Run `pnpm --filter @crm/api test legends.service` → FAIL (service not rewritten).
