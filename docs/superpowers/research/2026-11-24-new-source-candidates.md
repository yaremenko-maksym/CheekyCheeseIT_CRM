# New vacancy source candidates found during the bookmarklet holdout run

**Date:** 2026-11-24. **Why:** while capturing a public holdout corpus for the bookmarklet extractor, every new
job site visited was also judged as a permanent source for automatic vacancy collection (owner request,
2026-11-24). The owner then asked to connect **all** viable open sources, not only the top five. The work order is
`.claude/tasks/task-sources-wave-3.md`.

**Shelf life:** this is a first-pass survey, not a terms review. Every "ToS unknown" below means the terms were
not read, never that access is allowed. The wave-3 task must re-read robots and terms before any adapter is built.

**Verdicts are provisional.** "add" here means "worth a terms read first", never "cleared to build": no "add" row
below has its terms read. A source is cleared only by the wave-3 Phase 1 terms read (or an owner decision where the
terms cannot be read). Robots lines for Pinpoint and Breezy are from the vendors' marketing hosts; tenant
subdomains were not checked. The Workable sitemap was fetched but its entries were not checked to be job URLs.

Method: public robots.txt read for each host, one test request per feed/doc, no accounts, no key requests.
**ToS pages were NOT readable for most hosts** (SPA shell, Cloudflare 403, or login wall). Where a ToS stance is
"unknown" it means exactly that, not "allowed". Every quoted robots line is fetched live from `https://<host>/robots.txt`.
Already-connected and previously rejected sites are skipped (list in the wave-3 task file, section "Skip").

Legend: access = public API / RSS / JSON feed / sitemap / HTML only / login. Fit is for IT outsource/outstaffing
(software, AI, EdTech, E-Commerce; remote / Ukraine / EU).

## Ranked candidates for the Phase 1 terms read (provisional, not cleared)

1. **jobs.workable.com** — `sitemap.xml` → job pages → JSON-LD `JobPosting`. No auth. Cross-employer discovery, large volume. Filter IT by title/category. Keep `ai-train=no` in mind (index only).
2. **Join.com** — `sitemap-jobs-index.xml` (in robots) → job pages → JSON-LD. No auth. EU/DACH remote-EEA roles. Official API is own-company only, so use pages.
3. **Pinpoint + Breezy watchlist connectors** — `postings.json` and `/json` per target employer. Documented (Pinpoint) or stable and observed (Breezy). Needs an employer list from the CRM.
4. **DevITjobs feed family** — `https://devitjobs.uk/api/jobsLight` JSON. Cheapest structured feed, fresh daily (673 jobs in 7 days) but 99% re-posts and 70 remote. **Gate: owner reads ToS** (unreadable here).
5. **Arc.dev** — sitemap + HTML pages, no JSON-LD JobPosting on the sampled page, so needs the HTML extractor. Remote developer roles. Respect `Crawl-Delay: 10` from robots.

Not ranked but worth an owner decision: **Adzuna** and **Careerjet** (both free API keys; I did not register).
Note: Pinpoint and Breezy robots cited are the vendors' marketing hosts; tenant subdomains were not checked separately.
Gaps: ToS text not read for any site except where noted; BambooHR and SuccessFactors live postings not captured; iCIMS pages were 410 or iframe-only.
